# 18. 무료 데이터 경로 — 외부 의존을 둘로 줄였다

2026-07-30. "무료 데이터를 가장 확실하게 받아올 수 있는 경로를 파악하는 게
중요하다"에 답한 기록이다.

무료 데이터로만 돌아가는 시스템에서 위험의 크기는 지표 개수가 아니다.
**외부에서 반드시 받아야 하는 시계열이 몇 개이고, 각각 대안이 몇 개인가**다.
소스가 죽거나 유료화되는 것은 예외가 아니라 예정된 일이다.

```bash
python3 tools/probe_sources.py            # 배포할 환경에서 직접 돌린다
python3 tools/probe_sources.py --series realized_cap
```

---

## 1. 결론 — 진짜 외부 의존은 2개다

지표 9개를 계산하는 데 쓰는 시계열은 7개다. 그중 **4개는 API 없이
계산된다.**

| 시계열 | 조달 | 근거 |
|---|---|---|
| **price** | 외부 필수 | 대체 불가 |
| **realized_cap** | 외부 필수 | UTXO 하나하나의 생성 시점 가격을 합산해야 나온다. 계산 불가 |
| supply | **계산** | 반감기 스케줄이 합의 규칙에 박혀 있다 |
| market_cap | **계산** | price × supply |
| issuance_btc | **계산** | supply 의 일간 차분 |
| issuance_usd | **계산** | issuance_btc × price |
| hashrate | 있으면 좋음 | 없으면 Hash Ribbons 하나만 결측 |
| active_addresses | 있으면 좋음 | 없으면 mcap_per_active 하나만 결측 |

`src/btc_core/datasources/derive.py` 가 그 계산을 한다. 실측이 있으면
손대지 않고, **없을 때만** 채운다.

### 실제로 얼마나 줄어드는가

가격과 실현시총만 담은 CSV로 리포트를 돌려 봤다.

| | 파생 켬 (기본) | `--no-derive` |
|---|---:|---:|
| 커버리지 | **100%** | 33% |
| BCS | **−64.4** | −59.0 |
| 밸류에이션 계열 | 정상 | **전체 결측** |
| 공급 계열 | Puell 정상 | **전체 결측** |
| 합의 게이트 | 통과 | **미달** (가격 계열 단독) |
| 실행 | 매집 1단 대기 | **커버리지 33% < 60% 로 금지** |

실측 전체로 계산한 BCS 는 −64.2 다. **파생만으로 −64.4** — 0.2점 차이다.

`--no-derive` 쪽이 중요하다. 파생이 없으면 가격 계열이 가중치 100% 를 먹고
**가격 이동평균만으로 사이클 위치를 판정하는 상태**가 된다. 합의 게이트가
그걸 막아서 실행은 안 되지만, 화면의 BCS 는 여전히 −59 라는 숫자를 보여준다.
파생은 그 상태 자체를 없앤다.

## 2. 파생값의 정확도

CoinMetrics 실측 `SplyCur` 대비 (n 은 유효일수):

| 기간 | 평균 절대오차 | 최대 | n |
|---|---:|---:|---:|
| 전 구간 | 5.845% | 4553.740% | 6,409 |
| 2011년+ | 0.295% | 6.650% | 5,687 |
| 2013년+ | 0.176% | 1.258% | 4,956 |
| **2015년+** | **0.079%** | 0.989% | 4,226 |
| **2020년+** | **0.011%** | 0.051% | 2,400 |

2009년 오차가 터무니없는 이유는 하나다. 그때는 해시레이트가 거의 없어서
블록이 10분보다 **훨씬 느리게** 나왔고, 이 모델은 반감기 구간 안에서 블록이
균일하게 나온다고 가정한다. 다만 그 시절은 가격 데이터도 없어서 지표 계산에
들어오지 않는다.

발행량은 **끝난 반감기 구간에서 구조적으로 정확하다.** 구간 경계가 실측
날짜이고 구간 총량이 210,000 × 보상으로 고정이기 때문이다.

| 구간 | 실측 | 파생 | 차이 |
|---|---:|---:|---:|
| 2012-11 ~ 2016-07 | 3,982.6 | 3,982.9 BTC/일 | +0.01% |
| 2016-07 ~ 2020-05 | 1,872.9 | 1,873.8 | +0.05% |
| 2020-05 ~ 2024-04 | 912.6 | 912.1 | −0.05% |
| 2024-04 ~ (진행중) | 451.9 | 455.6 | **+0.82%** |

진행 중인 구간만 벌어져 있고, 원인은 **다음 반감기 날짜가 추정값**이라는
것뿐이다(2028-04-01). 늦게 오면 파생 일간 발행량이 그만큼 과대평가된다.
보정하지 않는다 — Puell 은 발행액을 자기 1460일 이동평균으로 나눈 비율이라
분자·분모에 같은 편차가 걸려 상쇄되고, 보정계수는 곧 또 하나의 임의
파라미터가 된다.

### 지표 수준에서의 차이

파생만으로 계산한 BCS 를 실측 BCS 와 16년 전 구간에서 비교했다.

| | 평균 절대차 | 최대 |
|---|---:|---:|
| 사이클 전환점 8곳 | **1.16점** | 5.15점 |
| 전 구간 (n=5,855) | 1.63점 | 93.58점 |
| 2015년+ (n=4,227) | 1.51점 | 29.83점 |

전환점 8곳에서 **부호가 뒤집히거나 국면이 바뀌는 곳은 없다.**

| 국면 | 날짜 | 실측 | 파생 | 차이 |
|---|---|---:|---:|---:|
| 고점 | 2013-11-30 | 74.6 | 74.5 | −0.1 |
| 저점 | 2015-01-14 | −98.2 | −98.2 | +0.0 |
| 고점 | 2017-12-17 | 89.3 | 89.2 | −0.0 |
| 저점 | 2018-12-15 | −86.6 | −88.5 | −1.9 |
| 고점 | 2021-11-10 | 52.0 | 51.8 | −0.1 |
| 저점 | 2022-11-21 | −82.7 | −82.6 | +0.1 |
| 고점 | 2025-10-06 | 50.7 | 55.8 | +5.2 |
| 저점 | 2026-06-06 | −73.7 | −71.8 | +1.9 |

밴드가 달라지는 날은 285/5,855 = **4.87%** 다. 대부분 밴드 경계 ±2점
안에서 걸치는 날이고, 최대 차이 93.58점은 2011-06-15 — 유통량 오차가 큰
시절이다. 연도별로 보면 2015년 이후 평균은 1.0~2.8점 사이다.

**그래서 파생은 실측의 대체가 아니라 보험이다.** 실측이 있으면 실측을 쓴다.
리포트 상단에 파생 사용 여부가 항상 뜬다 — 0.08% 오차라도 실측과 파생은
다른 것이므로 화면에서 사라져서는 안 된다.

## 3. 소스 지도 — 무엇을 어디서

`tools/probe_sources.py` 에 선언으로 들어 있다. 표는 그 요약이다.

### price — 필수, 대안 5개

| 순위 | 소스 | 이력 시작 | 무료 제약 |
|---|---|---|---|
| 1 | CoinMetrics community | 2010-07-18 | 키 없음, 초당 제한, 하루 지연 |
| 2 | blockchain.info charts | **2009-01-03** | 키 없음, 차트별 개별 요청 |
| 3 | Bitstamp OHLC | 2011-08-18 | 요청당 1,000봉 — **거래소 중 최장** |
| 4 | Coinbase Exchange candles | 2015-07-20 | 요청당 300봉 (16년치 20회 페이징) |
| 5 | Binance klines | 2017-08-17 | USDT 표시, 일부 지역 차단 |

CoinGecko 무료는 2024년 정책 변경으로 **일별 이력을 365일까지만** 준다.
현재가 확인용으로는 쓸 수 있지만 16년 이력이 필요한 이 시스템에는 부적합이다.
Kraken 은 일봉을 720개만 줘서 같은 이유로 부적합이다.

### realized_cap — 필수, 대안 2개. **여기가 진짜 급소다**

| 순위 | 소스 | 방식 |
|---|---|---|
| 1 | CoinMetrics community | `CapMVRVCur` 로 역산 (`CapRealUSD` 는 403) |
| 2 | BGeometrics bitcoin-data.com | `/v1/mvrv`, `/v1/realized-price` 무료 엔드포인트 |

실현시총은 **계산으로 대체할 수 없는 유일한 시계열**이다. 없으면 MVRV Z 와
NUPL 이 빠지고 밸류에이션 계열(가중치 40)에 서멀캡만 남는다. 대안이 2개뿐인
것이 이 시스템에서 가장 큰 단일 장애점이다.

CoinMetrics 의 역산은 정보 손실이 없다 — MVRV 의 정의가 곧 시총÷실현시총이고
MVRV 자체를 CoinMetrics 가 산출하므로 나눗셈 한 번으로 되돌려진다.

### hashrate / active_addresses — 없어도 멈추지 않는다

hashrate: CoinMetrics → blockchain.info(`hash-rate`) → mempool.space.
active_addresses: CoinMetrics → blockchain.info(`n-unique-addresses`).

각각 지표 하나(Hash Ribbons / mcap_per_active)만 결측되고 나머지는 다 돈다.
계열 가중치가 커버리지에 따라 재정규화되므로 점수 자체는 계속 나온다.

### LRS 거시 축

FRED CSV(`DFII10` 실질금리, `DTWEXBGS` 달러지수, `WM2NS` M2)는 키 없이
열린다. Stooq 가 달러지수 대안이다. **LRS 는 BCS 를 바꾸지 않고 실행 크기만
0.75~1.25배로 조절**하므로 없어도 사이클 위치 판정에는 영향이 없다.

## 4. 이 환경에서의 실측 결과

12개 후보를 찔러 본 결과다.

    O  CoinMetrics community      200
    X  blockchain.info charts     차단 (Tunnel connection failed: 403)
    X  BGeometrics bitcoin-data   차단
    X  Bitstamp / Coinbase / Binance / Kraken / CoinGecko   차단
    X  mempool.space / Blockchair 차단
    X  FRED / Stooq               차단

**이 컨테이너에서는 CoinMetrics 하나만 열린다.** 조직 프록시 정책이고
우회하지 않는다. 그래서 `data/market.csv` 를 저장소에 두고 오프라인으로
재현 가능하게 유지한다.

이것이 `probe_sources.py` 가 존재하는 이유다. **네트워크 정책은 환경마다
다르다** — 회사 프록시, 국가 차단, 클라우드 IP 거부. 배포할 곳에서 직접
돌려보는 것이 유일한 확인 방법이고, 종료 코드가 0/1 이라 배포 전 점검에
그대로 넣을 수 있다.

## 5. 그래서 남는 위험은 정확히 무엇인가

1. **realized_cap 의 대안이 2개뿐이다.** 둘 다 막히면 밸류에이션 계열
   가중치 40 중 서멀캡만 남는다. 이때 합의 게이트가 살아 있어서 가격 계열
   단독 실행은 여전히 막히지만, 사이클 위치의 해상도는 확실히 떨어진다.
   **유료 피드 우선순위 1번이 온체인 구독**인 이유다([docs/16](16-지표-전수조사.md)).
2. **다음 반감기 날짜가 추정값이다.** 2028-04-01 이 틀리면 진행 구간의
   파생 발행량이 어긋난다. 지금 +0.82% 다. 반감기가 실제로 오면
   `HALVING_SCHEDULE` 과 `indicators.HALVINGS` 를 같이 갱신해야 하고,
   `derive.py` 의 import 시점 검사가 둘이 어긋나면 즉시 깨뜨린다.
3. **커뮤니티 티어는 언제든 좁아질 수 있다.** `CapRealUSD` 가 이미 403 이다.
   `CapMVRVCur` 도 같은 길을 갈 수 있다. 그때 BGeometrics 가 유일한 경로가
   된다.
