# 19. BCS 를 점 대신 구간으로 — 그리고 시각화

2026-07-30. [15 교차자산 검증](15-교차자산-검증.md) 5절에서 다음 과제로 꼽아
둔 것을 실행한 기록이다.

> **3번을 다음에 하는 것을 권한다.** 자유도를 늘리지 않으면서 "소수점을 믿지
> 말라"는 경고를 숫자로 만든다.

```bash
python3 tools/export_viz.py --csv data/market.csv --stats-only
python3 tools/build_viz.py  --csv data/market.csv          # viz/site/ 에 세 장
```

---

## 1. 왜 점 하나가 문제인가

`BCS −63.9` 라고 쓰면 사람은 그 소수점을 믿는다. 그런데 이 시스템은
[docs/14](14-과적합-노출도.md)에서 이미 **앵커를 ±50% 왜곡하면 BCS 가 33점
움직인다**는 것을 측정해 두었다. 33점이 움직이는 숫자를 소수 첫째 자리까지
적어 두는 것은 정직하지 않다.

그리고 이 시스템의 목적이 **"지금이 저점 부근인가 고점 부근인가"** 를 말하는
것이라면, 필요한 출력은 좌표 하나가 아니라 **범위**다.

## 2. 구간의 출처 — 파라미터를 하나도 안 늘린다

이게 이 방식을 고른 유일한 이유다.

"±10 정도로 보라"는 상수를 박으면 **그 10이 또 하나의 조정 숫자가 된다.**
자유도가 이미 269개인데 거기에 하나를 더 얹으면서 "불확실성을 표시했다"고
말하는 것은 앞뒤가 안 맞는다.

그래서 **잭나이프**를 쓴다. 지표를 하나씩 빼고 다시 계산한 값들의 최소·최대다.

```
구간 = [ min(BCS, BCS₋₁, …, BCS₋₉),  max(BCS, BCS₋₁, …, BCS₋₉) ]
       BCS₋ᵏ = k번째 지표를 결측으로 두고 계산한 BCS
```

새 숫자가 없다. 폭은 데이터가 정한다.

### 구간이 답하는 질문

**"지표 하나가 틀렸거나 없었다면 판정이 달라졌을까?"**

이 질문은 형식적인 것이 아니다. 밸류에이션 계열의 집계가 `max_abs` 라
**그 안에서 가장 극단인 지표 하나가 BCS 의 40% 를 혼자 끌고 간다.** 그 지표를
빼면 차상위가 올라오고 점수가 움직인다. 그 움직임의 크기가 곧 "이 판정이 지표
하나에 얼마나 매달려 있는가"다.

지표를 빼면 계열이 통째로 사라지는 경우도 있다(그 계열의 유일한 생존 멤버였을
때). 그때는 가중치가 재정규화되어 다른 계열의 지분이 커진다 — 실제로 그
데이터가 없을 때 벌어지는 일과 같으므로 그대로 둔다.

## 3. 실측 — 폭이 얼마나 되는가

16년 전 구간(5,855일):

| | 값 |
|---|---:|
| 평균 폭 | 19.1점 |
| **중위 폭** | **16.6점** |
| p10 / p25 | 5.8 / 9.6 |
| p75 / p90 | 25.2 / 34.4 |
| p99 / 최대 | 70.0 / 138.3 |

중위 16.6점은 [docs/14](14-과적합-노출도.md)의 교란 실험이 낸 ±16점과
거의 같다. **완전히 다른 방법으로 재서 같은 크기가 나왔다** — 앵커 왜곡은
파라미터를 흔들고, 잭나이프는 지표를 뺀다. 둘이 일치하는 것은 그 폭이 이
시스템의 실제 해상도라는 뜻이다.

### 가장 중요한 숫자

    구간이 한 밴드 안에 온전히 들어오는 날  2,682 / 5,855 = 45.8%

**절반이 조금 안 되는 날만 국면을 하나로 말할 수 있다.** 나머지 날은
"싼 편 ~ 저점 부근" 처럼 두 국면에 걸쳐 있다. 이건 결함이 아니라
**측정된 사실**이고, 점 하나로 표시할 때는 보이지 않던 것이다.

### 전환점에서의 구간

| 국면 | 날짜 | 구간 | 폭 | 한 밴드 |
|---|---|---|---:|---|
| 고점 | 2013-12-04 | +70.2 ~ +91.2 | 21.0 | O |
| 저점 | 2015-01-14 | −99.4 ~ −96.6 | 2.8 | O |
| 고점 | 2017-12-16 | +79.9 ~ +98.8 | 18.9 | O |
| 저점 | 2018-12-15 | −88.9 ~ −84.5 | 4.4 | O |
| 고점 | 2021-11-08 | +45.7 ~ +59.1 | 13.4 | O |
| 저점 | 2022-11-09 | −97.2 ~ −70.5 | 26.7 | O |
| 고점 | 2025-10-06 | +42.6 ~ +54.8 | 12.2 | **X** |
| 저점 | 2026-06-30 | −70.5 ~ −65.2 | 5.3 | **X** |

> 날짜가 [docs/21](21-전수-코드점검.md) 에서 갱신됐다. 전에는 손으로 고른
> 날짜를 썼는데, 실제 극값 종가일과 최대 24일 어긋나 있었고 **고른 쪽이 결과를
> 좋아 보이게** 하고 있었다. 이제 데이터에서 뽑는다.

여기서 두 가지가 새로 보인다.

**(가) 저점이 고점보다 대체로 확실하다.** 저점 네 곳의 폭이 2.8 / 4.4 / 26.7 /
5.3 인데 고점은 21.0 / 18.9 / 13.4 / 12.2 다. **저점에서는 지표 9개가 서로
동의하고, 고점에서는 어느 지표를 남기느냐에 따라 판정이 갈린다.** 이건
[docs/11](11-지표-발굴-2차.md)에서 확인한 "고점 탐지력이 사이클마다 약해진다"의
다른 얼굴이다.

**(나) 2025 고점의 구간 하단이 사다리 첫 계단 아래다.** 분배 첫 계단이
+45 인데 2025 고점의 하단이 +42.6 이다. 즉 **"첫 계단이 열렸다"는 사실 자체가
지표 하나에 매달려 있었다.** 점수만 보면 +50.7 로 여유가 있어 보이지만 구간을
보면 그렇지 않다. 2021 고점도 하단 +45.7 로 간신히 넘는다. 백테스트가
"4/4 고점에서 분배가 열렸다"고 말한 것을 이 표가 조금 깎아내린다.

## 4. 표시 전용이라는 약속

**구간은 실행 규칙에 개입하지 않는다.** 밴드·사다리·DCA 는 점수(`bcs`) 하나로만
결정된다.

이유는 하나다. 구간으로 게이트를 걸면 "구간이 밴드를 걸치면 보류" 같은 **새
규칙**이 생기고, 그건 자유도를 늘리는 일이다. 불확실성을 표시하려고 만든
장치가 불확실성을 늘리면 앞뒤가 안 맞는다.

이 약속은 테스트로 못 박혀 있다.

```python
# tests/test_interval.py
def test_the_interval_never_changes_the_plan(cfg):
    rebuilt = build_plan(cfg, bcs=snap.bcs, ...)
    assert rebuilt.band_key == snap.plan.band_key
    assert rebuilt.dca_multiplier == snap.plan.dca_multiplier
```

대신 **경고로는 남는다.** 구간이 밴드 경계를 걸치면 `Snapshot.warnings` 에
그 사실이 들어가고, 리포트를 안 보고 JSON 만 쓰는 경우에도 사라지지 않는다.

## 5. 리포트에서 어떻게 보이는가

```
  BCS  사이클 위치    -66 ~ -60   ───├●─────┼──────────
       저점 부근 — 예비 현금 넣기 시작 (점 -62.8)
       폭 5점 — 하단은 'Hash Ribbons 상태' 제외 시, 상단은 'Puell Multiple' 제외 시
```

구간이 두 밴드에 걸치면 이렇게 바뀐다.

```
  BCS  사이클 위치    -76 ~ -55   ──├●━┤────┼──────────
       바닥권 ~ 저점 부근 — 두 국면 사이 (점 -74.3)
       실행은 바닥권 기준 — 예비 현금 집중 투입
```

**"실행은 … 기준"** 이라고 따로 적는다. 표시는 두 국면이지만 실행은 점수가
정한다는 것을 화면에서 분리해 두어야 한다.

## 6. 시각화

`viz/_head.html` + `viz/_script.html` + `viz/*.body.html` 을 `tools/build_viz.py`
가 합쳐 **자기완결 HTML 세 장**을 만든다(처음에는 한 장이었는데 7,500px 가 되어
나눴다).
CSS·JS·데이터를 전부 한 파일에 굽는다 — 외부 요청이 하나라도 있으면 그 요청이
막힌 환경에서 빈 화면이 나오고, **무료 데이터로 돌아가는 시스템에서 그건
"안 보인다"와 같다.**

담은 것은 여섯 개다.

1. **계기판** — 눈금이 그려진 −100 ~ +100 자 위에 현재 구간을 브래킷으로 얹는다.
   큰 숫자가 아니라 **자 위의 위치**가 주인공이다. 이 시스템이 무엇인지에 대한
   시각적 진술이다.
2. **16년 이력** — 구간을 리본으로, 대표값을 가는 선으로. 배경이 밴드다
   (위로 갈수록 따뜻하고 아래로 갈수록 차갑다 — 비싼 쪽/싼 쪽이 원래 온도 비유다).
3. **가격(로그)** — 같은 가로축의 별도 차트. **한 그림에 겹치지 않는다.**
   축이 둘이 되면 없는 상관을 만들어 낸다.
4. **성적표** — 전환점 8곳의 구간을 한 축에 늘어놓는다. 가장 낮은 고점과 가장
   높은 저점 사이 **118점의 빈 공간**이 이 지표의 핵심 증거다.
   (데이터가 [매일 갱신](22-자동갱신과-두-언어.md)되므로 이 숫자는 하루하루
   조금씩 움직인다. 마지막 저점이 아직 **잠정**이고 4년 퍼센타일 창이 함께
   미끄러지기 때문이다 — 화면의 값이 문서와 1점 다르면 그 이유다.)
5. **계열 3개** — 가중치·구성 지표·최근 4년 점수.
6. **불확실성** — 구간 폭 분포와 45.8% 라는 숫자.

데이터는 주 단위로 추리고(전환점 주변 ±45일과 최근 400일은 일 단위) 좌표를
배열로 눕혀 담는다. 그래야 16년치가 100KB 안쪽에 들어온다.

### 시각화를 만들다 찾은 것

**계열 커버리지가 멤버 결측을 숨긴다.**

마지막 날의 커버리지가 100% 인데 BCS 가 −62.8 에서 −50.4 로 12점 튀었다.
원인은 CoinMetrics 커뮤니티 티어의 하루 지연이었다 — 마지막 행에 실현시총이
없어서 MVRV Z 와 NUPL 이 결측이고, 밸류에이션 계열은 `max_abs` 라 **서멀캡
하나만 살아 있어도 "계열 있음"** 이 되어 커버리지가 100% 로 나온다.

두 가지를 고쳤다.

1. **파생을 날짜 단위로 채운다.** `backfill` 이 시계열 *전체*가 없을 때만
   채우고 있었는데, 현실에서 가장 흔한 경우는 **마지막 하루가 비는 것**이다.
   오늘 값을 보려고 만든 지표에서 가장 중요한 하루를 놓치고 있었다.
   ([docs/18](18-무료-데이터-경로.md))
2. **헤드라인 기준일은 지표 9개가 전부 살아 있는 마지막 날**로 잡는다.
   커버리지가 아니라 **멤버 결측 수**로 판정한다.

구간이 이걸 먼저 알려줬다는 점도 기록해 둘 만하다. 그날의 폭이 5.3점에서
17.6점으로 벌어져 있었다 — **커버리지는 100% 라고 했지만 잭나이프는 판정이
지표 하나에 매달려 있다고 말했다.**
