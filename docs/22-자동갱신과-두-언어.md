## 1. 자동 갱신 — 문제는 "잇기"가 아니라 "잘못 잇지 않기"다

`data/market.csv` 는 16년치 관측이고 **이 시스템의 유일한 입력**이다. 자동
갱신을 붙인다는 것은 사람이 안 보는 동안 그 파일을 덮어쓰는 코드를 두겠다는
뜻이다. 그래서 도구를 짜면서 시간을 쓴 곳은 받아오는 쪽이 아니라 거부하는
쪽이었다.

### 겹침 대조가 핵심이다

이어 붙일 부분만 보면 새 값이 그럴듯한지 알 수 없다. **이미 갖고 있는 날짜와
대조하면 알 수 있다.**

```
겹침 401일 중 가격이 2% 넘게 다른 날이 3일을 넘으면 → 아무것도 쓰지 않고 중단
```

이 한 검사가 조용히 망가지는 경로를 대부분 잡는다.

| 사고 | 걸리는 곳 |
|---|---|
| 다른 자산(ETH)을 받아옴 | 겹침 가격이 20배 차이 |
| 센트 단위로 바뀜 | 겹침 가격이 100배 차이 |
| API 스펙이 바뀌어 다른 필드가 옴 | 가격이 비어 있음 → 즉시 중단 |
| 응답이 잘려서 일부만 옴 | 병합이라 손해 없음, 몇 일 받았는지 출력 |
| 최신 며칠이 아직 null | 그 칸만 건너뜀 (아래 참조) |

겹침이 5일 미만이면 **대조 자체가 대조가 아니므로** 그것도 거부한다. 기존
파일이 없을 때만 예외로 두고 "첫 수집"이라고 적는다.

### 하루 급변은 막고, 진짜 폭락은 통과시킨다

단위 오류를 잡으려고 "하루에 얼마 이상 움직이면 중단"을 걸면, 실제 폭락일에
갱신이 멈춘다. 실측을 보면 이렇다.

```
2013-04-11  +94%      2020-03-12  −60%
2012-08-19  +48%      2013-04-10  −43%
```

그래서 **중단선은 5배(Δln 1.6)** 로 두고 — 그건 단위가 바뀐 것으로밖에
설명이 안 된다 — 42% 이상은 경고로만 남긴다. 날짜가 하루 차이가 아닌 쌍은
아예 세지 않는다. 구멍 건너뛴 두 날을 하루 변동으로 세면 안 된다.

### 이미 있는 값을 빈 값으로 덮지 않는다

이건 [docs/18](18-무료-데이터-경로.md)에서 배운 것을 병합 규칙으로 옮긴 것이다.
CoinMetrics 커뮤니티 티어는 **최신 하루의 실현시총이 비어 있다.** 시계열을
통째로 갈아 끼우면 어제 받아 둔 값이 오늘 사라진다.

그래서 병합은 **칸 단위**다. 열마다 "새 값이 있을 때만" 얹는다. 그리고 그
규칙이 지켜졌는지 사후에 다시 센다 — 어떤 열도 칸 수가 줄면 안 된다.

실제로 이번 실행에서 그 효과가 바로 나왔다.

```
병합    새 날짜 1일 (2026-07-29) · 빈 칸 채움 market_cap 1, realized_cap 1, supply 1
```

`2026-07-28` 은 어제 받을 때 시총·유통량이 비어 있었고, 오늘 받아 채워졌다.
그 결과 기준일이 `2026-07-28` 에서 `2026-07-29` 로 하루 앞으로 왔다.

### 되돌리기 — git 이 백업이 아니다

`data/market.csv` 는 `.gitignore` 에 있다. 매일 1MB 짜리 CSV 를 커밋하면
1년에 100MB 가 쌓인다. 그래서 교체 직전 파일을 `market.csv.bak` 으로 남긴다.

그리고 진짜 원본은 API 다. **전 구간을 다시 받으면 증분으로 이어 온 파일과
바이트 단위로 같은 파일이 나온다** — 1.7초 걸린다. 그 동일성이 성립하니까
CI 는 매번 전 구간을 받아도 되고, 되돌릴 때 "다시 받으면 된다"고 말할 수 있다.
`tests/test_refresh.py::test_full_and_incremental_agree` 가 그 성질을 지킨다.

쓰기 자체는 임시 파일 → 다시 읽어 확인 → 제자리로 옮기기 순이다. 중간에
죽어도 원본은 그대로다.

### 매일 도는 것

`.github/workflows/refresh-data.yml` 이 02:20 UTC(한국 11:20)에 돈다. 자정
직후를 피한 이유는 커뮤니티 티어가 전날 데이터를 채우고 난 뒤여야 하기
때문이다. 저장소에 남는 것은 **다 구운 페이지 세 장**이고 CSV 는 남기지 않는다.

순서에서 한 가지가 중요하다 — **사이트를 굽기 전에 테스트를 돌린다.** 데이터가
바뀌어 계산이 깨졌으면 깨진 페이지를 커밋하는 것보다 멈추는 것이 낫다.

> GitHub Actions 의 `schedule` 은 기본 브랜치의 워크플로만 실행한다. 작업
> 브랜치에 있는 동안에는 수동 실행으로만 돈다.

### 화면에 뜨는 신선도

자동 갱신을 붙였으면 **멈췄을 때 보여야 한다.** 머리글에 `데이터 1일 전`
이라고 적고, 사흘을 넘기면 붉게 바꿔 `갱신이 멈췄을 수 있습니다` 를 붙인다.

이 값은 **보는 시점에** 센다. 구울 때 계산해 넣으면 "1일 전"이 하루만 지나면
거짓이 된다. 페이지에는 마지막 날짜만 굽고, 며칠 전인지는 브라우저가 센다.

## 2. 두 언어

버튼 하나로 한국어·영어를 바꾼다. 선택은 기억하고, 처음 오는 사람에게는
브라우저 설정을 따른다.

### 어긋남이 유일한 위험이다

두 언어로 띄우기로 하면 새 실패 방식이 하나 생긴다. 지표를 하나 추가하고 영어를
잊으면 **영어 화면 한가운데에 한국어가 남는다.** 그건 번역하지 않은 화면보다
나쁘다. 어긋날 수 있는 곳이 셋이고, 셋 다 테스트로 막았다.

| 무엇 | 한국어 | 영어 | 지키는 테스트 |
|---|---|---|---|
| 본문 산문 | `viz/*.body.html` 의 `data-t` | `viz/_i18n.html` | 키 집합 일치 (양방향) |
| 화면 생성 문장 | `_script.html` 의 `TX.ko` | `TX.en` | 키 집합 일치 |
| 설정 문자열 | `config/strategy.yaml` | `config/strings.en.yaml` | 필드 단위 일치 |

**양방향**인 것이 중요하다. 빠진 키만 잡으면 지워진 문단의 잔해가 사전에
쌓인다.

### 한국어를 원본으로 두고 되돌린다

영어 사전은 갖고 있지만 한국어 사전은 없다. HTML 에 이미 한국어가 있으니,
처음 언어를 바꿀 때 그 `innerHTML` 을 기억해 두고 되돌릴 때 쓴다. 사전을 두 벌
두면 한쪽만 고쳐지는 일이 생긴다.

이 방식에는 조건이 하나 붙는다 — **`data-t` 는 겹쳐 쓸 수 없다.** 부모의
`innerHTML` 을 갈아 끼우면 그 안의 `data-t` 자식이 사라져서 되돌릴 원본을
잃는다. 그 구조를 테스트가 못 박는다(HTML 을 실제로 파싱해서 중첩을 찾는다).

### 문장을 쪼개지 않는다

`"아홉 개 중 " + n + "개가 싼 쪽에"` 같은 조립은 어순이 다른 언어에서 무너진다.
그래서 숫자가 끼어드는 문장은 **언어마다 함수 하나**로 둔다.

```js
indNote: (below, total, lo, hi, spread) =>
  (below === total ? `${total}개가 전부` : `${total}개 중 ${below}개가`) + ` 한가운데…`
```

`below === total` 분기가 붙은 이유도 여기서 나왔다. 영어로 "9 of the nine" 이
되어 어색했다.

### 번역하면서 찾은 것

영어를 붙이는 과정에서 **한국어 쪽 버그 세 개**가 드러났다.

1. **계열 이름이 두 벌이었다.** 툴팁만 `밸류에이션 / 가격·추세 / 공급·채굴`
   이라고 쓰고 나머지는 설정의 `원가 대비 / 평균가 대비 / 채굴 상황` 을 쓰고
   있었다. 성적표 표의 마지막 세 열도 페이지에 하드코딩돼 있었다. 둘 다
   설정에서 읽게 고쳤다.
2. **상태 이름 하나가 없었다.** Hash Ribbons 는 숫자가 아니라 상태를 내는데,
   상태가 넷(`recovery` `capitulation` `normal` `expansion`)인데 화면 표에는
   셋만 있었다. `expansion` 인 날에는 화면에 **`expansion` 이라고 그대로**
   적혔다. 게다가 그 표에는 쓰이지도 않는 `buy` `neutral` 이 들어 있었다.
   이제 두 언어 다 설정이 소유하고, 테스트가 `states` 와 화면 이름을 대조한다.
3. **`나눠 팔기` 문구가 애매했다.** "단계를 다 밟아도 60% 까지만 줄어듭니다"
   가 60% 를 판다는 뜻인지 60% 가 남는다는 뜻인지 읽히지 않았다. 사다리 합이
   60% 이고 남는 것이 40% 다 — "보유량의 60% 까지만 팝니다"로 고쳤다.

세 번째는 번역 없이는 눈에 띄지 않았을 것이다. 같은 뜻을 다른 언어로 다시 쓰면
원문이 무엇을 말하지 않았는지가 보인다.

## 3. 두 테마

`data-theme` 을 명시적으로 설정하고 기억한다. 처음에는 OS 설정을 따른다.

깜빡임을 막는 곳이 한 군데 있다. 테마 적용을 본 스크립트에서 하면, OS 가
밝은데 어둡게 골라 둔 사람은 **흰 화면이 한 번 번쩍인 뒤** 어두워진다. 그래서
`<style>` 바로 뒤에 localStorage 를 읽는 인라인 스크립트를 둔다 — 첫 페인트
전에 끝난다.

## 5. 겹침 검사를 자동화했다

영어는 같은 뜻이 한국어보다 길다. 차트 안 라벨은 자리가 정해져 있어서 그 길이
차이가 그대로 **글자 겹침**이 된다. 눈으로 보고 넘기면 폭 하나만 달라져도 다시
깨진다. 그래서 브라우저에서 SVG 안 `<text>` 의 사각형을 전부 꺼내 짝마다
겹침을 재는 검사를 붙였다 — 3장 × 2언어 × 4폭 = 24가지.

처음 돌렸을 때 36건이 나왔고, **그중 여섯 곳은 영어와 무관한 한국어 화면의
겹침**이었다.

| 어디 | 무엇이 겹쳤나 | 고친 방법 |
|---|---|---|
| 이력 차트 | `반감기` × 2013 고점 값 `+89` | 좁은 화면에서는 글자를 빼고 선만 |
| 이력 차트 | 연도 눈금 × 2015 저점 값 `-98` | 자리가 없으면 반대편으로 넘김 |
| 폭 분포 | 축 이름 × 꼬리 설명 | 두 줄로 나눔 |
| 계열 차트 | 선 끝 갈래 이름이 그림 밖으로 | 자리가 없으면 생략(범례에 이미 있다) |
| 성적표 | 행 라벨 `bottom 15.01` 이 왼쪽으로 | 영어일 때 왼쪽 여백을 넓힘 |

지금은 24가지 전부 0건이다.

## 6. 점검에서 더 나온 것 — CSV 를 조용히 갉아먹는 경로 둘

경계 조건 14가지를 밟다가 새로 찾았다. 둘 다 **자동 갱신을 붙이면서 생긴** 것이
아니라, 붙이는 바람에 **위험해진** 것이다.

**모르는 열이 사라진다.** `read_cells` → `write_cells` 왕복은 `COLUMNS` 에 없는
열을 통째로 버린다. 손으로 열을 하나 추가해 둔 사람은 갱신 한 번에 그것을
잃는다. 사람이 직접 돌릴 때는 눈에 띄지만, 매일 자동으로 도는 코드에서는 아무도
안 본다.

**숫자로 안 읽히는 칸이 빈 칸이 된다.** `"60,000.0"` 처럼 쉼표가 들어간 칸을
`read_cells` 는 조용히 결측으로 넘긴다. 그 상태로 저장하면 그 칸은 빈 칸이 된다.
`load_csv_bundle` 은 이 경우 경고를 냈는데 `read_cells` 는 안 냈다.

둘 다 **읽는 쪽이 알려주고 갱신이 거부하게** 고쳤다. `--check` 는 쓰지 않으므로
경고만 하고 계속한다.

이 두 개가 이 작업의 성격을 잘 보여준다. 자동화는 기존 코드의 조용한 결함을
**위험한 결함으로 승격시킨다.** 사람이 매번 보고 있을 때는 "이상하네" 하고 넘길
수 있던 것이, 아무도 안 볼 때 도는 코드에서는 데이터 손실이 된다.

그 밖에 같이 고친 것:

- 임시 파일 이름에 PID 를 넣었다. 두 실행이 겹치면 서로의 임시 파일을 지웠다.
- 겹침이 짧을 때 허용 오차도 같이 줄인다. 겹침 1일에 3일까지 허용하면 그 1일이
  20배 달라도 통과한다 — 대조를 한 것이 아니다.
- 기존 파일이 5일보다 짧은 경우와 창을 좁게 잡은 경우를 구분한다. 앞쪽에
  "`--days` 를 늘리세요"라고 하면 늘려도 안 되는 것을 늘리라고 말하는 셈이다.
- 워크플로가 커밋 메시지에 넣을 기준일을 `sed` 로 뽑는데, 괄호 안 문구까지
  같이 잘려 들어가고 있었다.

## 7. 처음 보는 사람 기준으로 다시 보기

사이트를 처음부터 끝까지 다시 읽으면서 **비트코인을 잘 모르는 사람이 이 페이지를
열었을 때** 어디서 막히는지 찾았다. 네 곳이었고 넷 다 고쳤다.

### (가) 큰 숫자가 아무 뜻이 없었다

첫 화면에서 가장 먼저 눈에 들어오는 것이 `−63 ~ −60` 이다. 처음 보는 사람에게
이건 **아무 정보가 아니다.** "63이 뭐 중에 63인가"를 알려면 밑의 눈금을 봐야 하고,
눈금을 봐도 "그래서 이게 낮은 건가" 는 여전히 남는다.

그래서 큰 숫자 바로 밑에 한 줄을 넣었다.

> 지난 16년을 통틀어 **아래에서 14% 지점**입니다 — 5,856일 가운데 오늘보다
> 싼 쪽이었던 날이 14% 뿐이라는 뜻입니다.

**새로 정한 숫자가 없다.** 오늘 점수보다 낮았던 날을 16년 일 단위 전체에서 센
비율일 뿐이다. 추린 시계열이 아니라 **일 단위 전체**로 세는 것이 중요해서
테스트로 못 박았다 — 추린 쪽은 최근 400일이 일 단위라 최근 구간이 과대
대표되고, 그러면 첫 화면의 그 한 줄이 조용히 틀린다.

### (나) 16년 그림에 "지금"이 없었다

성적표(02장)에는 현재 위치를 세로선으로 그어 두었는데, 정작 **첫 장의 16년
그림에는 오늘이 어디인지 표시가 아예 없었다.** 이 페이지의 주장이 "지금이 과거
어디쯤인가" 인데 그 그림에 지금이 없었던 것이다.

오늘 수준에 **가로 점선**을 그었다. 세로선보다 이쪽이 낫다 — 선이 지나가는 곳이
전부 오늘과 같은 자리였던 때라서, **"과거에 이런 적이 몇 번 있었고 그 뒤에 어떻게
됐나"가 그림 하나로 읽힌다.** 지금 값(−61)에서는 2012·2015·2018·2022·2024 를
지나간다.

점선을 그었으면 범례에도 넣어야 한다. 설명 없는 선은 없는 선보다 나쁘다.

### (다) 계기판의 현재 표시가 실오라기만 했다

범위가 좁을 때(오늘은 3.4점 = 자 전체의 1.7%) 브래킷이 거의 안 보였다. 폭은
사실대로 두고 **위에 삼각형을 얹어** 위치를 찍는다.

### (라) 그림에 대체 텍스트가 없었다

이 페이지는 그림이 본체라, 화면 낭독기로 보면 거의 빈 페이지였다. 차트 여섯 개에
`role="img"` 와 설명을 붙였다. 설명은 캡션과 같은 숫자로 만든다 — 따로 적으면
어긋난다.

### (마) 그림을 마우스로만 짚을 수 있었다

크로스헤어와 툴팁이 마우스·터치 전용이라, 키보드만 쓰는 사람은 **특정 날짜를
짚어 볼 방법이 없었다.** 대체 텍스트로 요약은 읽히지만 "2022년 11월에는 얼마였나"
는 물어볼 수가 없다.

크로스헤어가 붙는 차트 세 개(16년 이력·가격·계열)를 탭으로 잡을 수 있게 하고
키를 붙였다.

| 키 | 하는 일 |
|---|---|
| `←` `→` | 하루(한 점) 이동 |
| `Shift+←/→`, `PageUp/Down` | 전체의 1/20 만큼 크게 이동 |
| `Home` `End` | 처음 · 끝 |
| `Esc` | 해제 |

두 가지를 신경 썼다.

**처음 들어오면 오늘부터 시작한다.** 왼쪽 끝에서 시작하면 지금에 닿는 데 5,000번을
눌러야 한다.

**툴팁은 낭독기가 읽지 않는다.** 마우스용으로 만든 것이라 포커스를 따라가지
않는다. 그래서 같은 내용을 `aria-live` 영역에 글로 따로 넣는다 — 화살표를 누를
때마다 "2022-11-09. BCS 구간 −97.2 ~ −70.5. 대표값 −83.8 …" 이 읽힌다.

여기서 함정을 하나 밟았다. **`svg` 요소는 다시 그려도 살아남는다** — 지워지는 것은
그 자식들이다. 그리기 함수는 창 크기가 바뀌거나 테마·언어가 바뀔 때마다 다시
도는데, 거기서 `svg.addEventListener` 를 부르면 리스너가 쌓인다. 화살표 한 번에 두
칸, 세 칸씩 움직이게 되고, **처음 열었을 때는 멀쩡해서** 잘 안 보인다. 한 번만
붙는 가드를 두고, 가드 밖에서 붙이지 못하게 테스트로 막았다.

탭 순서를 훑다가 하나 더 나왔다. 가로 스크롤이 되는 표 상자를 브라우저가 자동으로
탭 대상으로 만드는데 **이름이 없어서** 낭독기에 "그룹"이라고만 떴다. 네 곳에
위 제목을 이름으로 붙였다(`aria-labelledby`) — 번역도 따라온다.

## 8. 설명이 그림과 어긋나 있었다

한 번 더 처음부터 읽으면서, 이번에는 **"여기를 보세요"라고 적어 둔 문장이 실제로
그것을 가리키는지**만 확인했다. 네 곳이 어긋나 있었다. 전부 그림을 고친 뒤 글을
안 고쳐서 생긴 것이다.

| 어디 | 적혀 있던 것 | 실제 그림 |
|---|---|---|
| 성적표 | "세로로 지나가는 **회색 선**이 지금 위치" | 지금 위치는 **색이 있는 선 + 삼각형**. 회색인 것은 빈 공간의 경계선이다 |
| 성적표 | "**테두리로 표시된** 빈 공간" | 양끝에 화살표가 달린 **치수선**으로 잰다 |
| 첫 장 | "**맨 오른쪽**은 직전에 이만큼이던 시기" | 맨 오른쪽은 갈래다. 그 열은 오른쪽에서 두 번째 |
| 규칙 | "지난 **15년**이 특별한 시기였을 수 있습니다" | 나머지는 전부 16년 |

첫 번째가 제일 나쁘다. 지시대로 회색 선을 찾으면 **빈 공간의 왼쪽 경계선**을
보게 되는데, 그게 지금 위치 바로 옆이라 그럴듯하게 틀린다.

세 번째는 자리로 가리켰던 것이 문제였다. 열 순서를 한 번 바꾸면 바로 틀린다.
이제 **이름으로** 가리킨다 — "'직전에 이만큼이던 때'는 …".

### 어림으로 자리를 잡던 곳을 전부 재게 했다

영어 라벨이 그림 밖으로 나가는 것을 고치다가, 글자 폭을 **글자 수 × 계수**로
어림하던 곳이 네 군데라는 것을 알았다. 같은 글자 수라도 `저점  15.01` 과
`bottom  Dec '18` 은 폭이 딴판이라, 언어를 하나 더 붙이거나 라벨을 조금만 손봐도
어림이 틀린다.

`measureText()` 를 만들어 **실제로 재게** 했다. 보이지 않는 글자 하나를 그려
`getBBox()` 로 재고 지운다. 성적표 왼쪽 여백, 빈 공간 라벨 상자, 계열 차트 끝
라벨 자리, 이력 차트의 "지금" 상자 — 네 곳 전부 실측이다.

그리고 영어 성적표의 행 라벨을 `13.12` 에서 `Dec '13` 으로 바꿨다. `13.12` 는
영어권에서 **12월 13일**로 읽힌다.

### 문서의 숫자는 스냅숏이다

매일 갱신하기로 한 순간부터, 문서에 적어 둔 숫자와 화면의 숫자가 갈린다. 실제로
"빈 공간 118점"이 화면에서 119점으로 뜬다(실측 118.5, 반올림 경계). 마지막 저점이
아직 **잠정**이고 4년 퍼센타일 창이 함께 미끄러지기 때문이다.

숫자를 쫓아다니며 고치는 대신 문서에 그 사실을 적었다. 화면이 살아 있는 값이고
문서가 그때의 기록이라는 것이 분명해야 한다.
