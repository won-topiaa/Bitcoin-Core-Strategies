# 14. 과적합 노출도 — 조정 숫자 269개 대 사이클 4개

2026-07-30. "기준이 너무 많아서 정작 현재 상황을 못 맞추는 게 아니냐"는
질문에 답한 기록이다. 말로 답하지 않고 세 가지를 재기로 했고,
`tools/robustness.py` 로 언제든 다시 돌릴 수 있게 만들었다.

```bash
python3 tools/robustness.py --csv data/market.csv
```

**결론 먼저: 우려는 절반 맞다.** 자유도 비율은 실제로 재앙적이다. 그런데
실행 결론(밴드와 적립 배수)은 거대한 교란에도 안 바뀐다. 진짜 약점은
파라미터 개수가 아니라 **고정 앵커가 사이클을 넘어 일반화되지 않는다**는
쪽이었고, 그건 측정으로 확인해서 고쳤다.

---

## 1. 자유도는 실제로 재앙적이다

| 항목 | 개수 |
|---|---:|
| BCS 지표 앵커 좌표 | 128 |
| LRS 앵커·상태 | 47 |
| 사다리 계단 | 21 |
| 밴드 경계 | 14 |
| 바닥선·매수구간 | 14 |
| LRS 가중·조정계수 | 12 |
| 프로파일 임계 | 10 |
| DCA 배수 | 7 |
| 합의 게이트 | 5 |
| 히스테리시스 | 4 |
| 범주형 상태값 | 4 |
| 계열 가중치 | 3 |
| **합계** | **269** |

유효 표본은 **사이클 4개**(2025 는 미완성이라 실질 3.5개)다.
**269 ÷ 4 ≈ 67.** 고전적 기준으로 이건 변명할 수 없는 비율이다.

다만 어느 숫자가 *데이터에 맞춰졌는지*는 항목마다 다르다.

| | 데이터에 맞췄나 |
|---|---|
| 지표 앵커 128개 | **그렇다.** 2025 사이클 최대값이 +0.90 이 되도록 재조정 |
| 프로파일 임계 10개 | **그렇다.** 그 전환점들을 보고 정했다 (그래서 표시 전용) |
| Puell 기준선 1460일 | 아니다. 반감기 간격(1458일)에서 나온 값 |
| 계열 가중치 40/33/27 | 아니다. 원래 30/25/20 을 결측 재정규화한 값 |
| 밴드·사다리·게이트 | 아니다(논리로 정함). 단 `rearm_opposite_bcs`, `confirm_max_gap_days` 는 **실측 실패를 보고 고쳤다** |

## 2. 그런데 실행 결론은 교란에 견딘다

앵커를 통째로 왜곡하고 계열 가중치를 균등으로 바꾸고 밸류에이션 집계를
뒤집어 봤다. 2026-07-28 기준.

| 교란 | BCS | 밴드 | DCA |
|---|---:|---|---|
| 앵커 x좌표 ×0.70 | −46.4 | 깊은 저평가 | ×2.0 |
| 앵커 x좌표 ×1.50 | −77.6 | 극단 항복 | ×2.5 |
| 앵커 점수 −0.20 편향 | −79.4 | 극단 항복 | ×2.5 |
| 앵커 점수 +0.20 편향 | −56.2 | 깊은 저평가 | ×2.0 |
| 계열 가중치 균등 | −70.0 | 깊은 저평가 | ×2.0 |
| 밸류에이션 집계 → 평균 | −63.6 | 깊은 저평가 | ×2.0 |
| (교란 없음) | −66.3 | 깊은 저평가 | ×2.0 |

**BCS 는 33점이나 움직이는데 밴드는 두 개, DCA 는 두 값(2.0/2.5)뿐이다.
둘 다 "적극 매수"다.** 정규화 방식을 바꿔도(`--adaptive-weight` 0.0 / 0.35 /
1.0 → BCS −67.8 / −66.3 / −64.2) 밴드는 같다.

이유는 구조에 있다. 판단이 층을 지날 때마다 정밀도가 버려진다.

    9개 지표 →(평균·max_abs)→ 3개 계열 점수 →(가중합)→ BCS 1개
              →(폭 25점 밴드)→ 7개 밴드 중 하나 →(굵은 임계 ±45,±55…)→ 실행

밴드 폭이 25점이라 BCS ±10 은 대개 밴드를 안 바꾼다. **조정 가능한 숫자가
많은 것과 결론이 그 숫자에 달린 것은 다른 문제다.** 이 시스템은 후자가 아니다.

거꾸로 말하면, **소수점을 근거로 행동을 바꾸면 안 된다**는 README 의 경고가
측정으로 뒷받침된 것이다. BCS −66 과 −72 는 같은 상황이다.

## 3. 진짜 약점 — 고정 앵커는 사이클을 넘지 못한다

같은 종류의 전환점에서 사이클마다 같은 값이 나와야 그 정규화가 일반화된다.
네 고점에서 BCS 를 재고 표준편차를 봤다.

| 정규화 | 2013고 | 2017고 | 2021고 | 2025고 | 고점σ | 분배 첫계단 열림 |
|---|---:|---:|---:|---:|---:|:--:|
| 고정 앵커만 (adaptive 0.0) | +80.6 | +90.5 | +60.1 | **+28.9** | 23.6 | 3/4 |
| 현행 (앵커 65% + 퍼센타일 35%) | +78.2 | +90.0 | +56.1 | +43.6 | 18.2 | 3/4 |
| **전 지표 퍼센타일만 (1.0)** | +74.6 | +89.3 | +52.0 | **+50.7** | **16.2** | **4/4** |

저점은 어느 방식이든 −73 ~ −99 로 일관된다. **문제는 전부 고점 쪽이다.**

그리고 이건 취향 문제가 아니다 — **분배 사다리 첫 계단이 BCS +45 다.**
고정 앵커만 쓰면 2025 고점에서 +28.9 밖에 안 나와 **아무것도 팔리지 않는다.**
현행도 +43.6 으로 미달이다. 앵커를 전혀 쓰지 않는 방식만 +50.7 로 넘긴다.

### 왜 이런가

앵커는 **마지막에 관측된 사이클에 맞춰져** 있다. 그래서 두 방향으로 다 틀린다.

- 옛 사이클에 맞춘 앵커는 앞으로 실패한다 — 재조정 전 앵커로는 2021 고점이
  +40.0, 2025 고점이 +13.4 였고 사다리가 한 계단도 발동하지 않았다(docs/07).
- 새 사이클에 맞춘 앵커는 뒤로 실패한다 — 앵커를 안 쓰는 방식이 2017 사이클
  분배 품질 10% → 24%, 2021 44% → 63% 로 **더 좋았다**.

**양방향으로 틀리는 것이 비정상 과정(non-stationary)의 정의다.** 고정 임계로는
못 잡는다. 퍼센타일 정규화는 파라미터가 창 길이 하나뿐이고 스스로 재조정된다.

### 고친 것

모든 수치 지표가 `history_4y` 를 내도록 해서 퍼센타일 경로를 열었다.
전에는 4개(MVRV Z, Puell, 서멀캡, 활성주소당 시총)만 가능했다.

- 기본값(0.35)에서 고점σ **19.3 → 18.2**, 2025 고점 **+41.1 → +43.6**,
  16년 분배 평단 **$26,658 → $27,053**
- `--adaptive-weight 1.0` 이 이제 **고정 앵커를 하나도 쓰지 않는 모드**가 됐다.
  128개 자유도를 통째로 끄고 돌릴 수 있다.

기본값을 1.0 으로 바꾸지는 않았다. 이유는 둘이다.

1. 앵커에는 백테스트가 아니라 **도메인 지식**이 들어 있다 — 예컨대 NUPL 의
   0.75(도취)·0(항복) 경계는 원문 3.4 에서 온 것이고, 퍼센타일은 그런
   "절대적으로 비싸다"를 표현할 수 없다. 퍼센타일은 늘 "자기 4년 범위 안
   어디쯤"만 말한다.
2. 퍼센타일 전용은 **모든 지표에 4년 이력을 요구**한다. 새 데이터셋의 첫
   4년은 통째로 결측이 되고, 2025 사이클 분배 품질은 오히려 조금 나빴다
   (64% → 58%).

## 4. 과적합이 확실한 곳 — 프로파일

저점 프로파일 5조건, 고점 프로파일 5조건. **임계 5개를 전환점 4개에 맞춘
것이라 구조적으로 과적합이다.** 그래서 보고된 정밀도 100% 는 표본 안
수치이고 실전 정밀도는 반드시 이보다 낮다.

바로 그 이유로 **점수에 넣지 않았다.** 표시만 하고 실행에는 영향을 주지 않는다.
"이 숫자는 못 믿는다"고 판단한 것을 시스템 밖으로 빼는 것이 이 저장소의
일관된 처리 방식이다(바닥선도 같다 — 가격으로만 보여주고 점수화하지 않는다).

## 5. 고칠 수 없는 것

파라미터를 아무리 줄여도 **사이클 표본이 4개**라는 사실은 안 바뀐다.
4년 주기 현상을 4번 관측한 것이고, 그중 마지막은 아직 안 끝났다.

그래서 이 시스템의 방어선은 통계가 아니라 구조다.

| 장치 | 무엇을 막나 |
|---|---|
| 계열 압축 + `max_abs` | 상관된 지표를 여러 표로 세는 것 |
| 폭 25점 밴드 | 소수점에 반응하는 것 |
| 분할 사다리 (10계단) | 한 판정에 전부 거는 것 |
| 코어 40% 불가침 | 시스템이 틀렸을 때의 전멸 |
| 합의 게이트 | 한 계열의 착시 |
| 반증 조건 5개 | 사후 합리화 |

**코어 40% 를 어떤 신호에도 팔지 않는다는 규칙이 이 문서 전체의 요약이다.**
269개 숫자가 다 틀렸을 경우를 위해 자산의 40% 는 애초에 이 시스템에
맡기지 않는다.

## 6. 다시 재는 방법

```bash
python3 tools/robustness.py --csv data/market.csv   # 자유도·교란·일반화
python3 tools/screen_candidate.py --csv data/market.csv   # 기존 지표를 관문에
```

지표를 추가하거나 앵커를 고칠 때마다 이 둘을 돌린다. 자유도가 늘었는지,
교란 내성이 나빠졌는지, 고점σ 가 커졌는지가 숫자로 나온다.
