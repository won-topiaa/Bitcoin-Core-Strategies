# 21. 전수 코드 점검 — 고른 날짜가 결과를 좋아 보이게 하고 있었다

2026-07-30. "코드 점검 전체 한번 싹 해줘"에 답한 기록이다.

정적 검사와 테스트는 원래 깨끗했다(pyflakes 0, 321 passed, audit 0). 그래서
**테스트가 안 보는 곳**을 찾아 들어갔고, 거기서 두 가지가 나왔다. 둘 다
"틀린 계산"이 아니라 **"리포트가 사실과 다른 말을 하는"** 종류다.

---

## 1. `--as-of` 가 날짜만 바꾸고 데이터는 안 바꿨다

```
$ btc-core score --csv data/market.csv --as-of 2018-12-15
  BCS / LRS 스냅샷   기준일 2018-12-15
  현재가 $63,728          ← 2026년 가격
  BCS -64.2               ← 2026년 점수
```

**기준일만 라벨로 바뀌고 계산은 최신 데이터로 돌고 있었다.** 리포트 전체가
거짓말을 하는 상태다.

원인은 한 줄이다. `engine.evaluate()` 가 `as_of` 를 `resolved_date`(표시용
날짜)에만 쓰고, 지표 계산은 `market.price.last` 를 봤다.

`MarketData.up_to(end)` 와 `Series.slice_to(end)` 를 추가해 기준일 이후를
잘라내게 했다. 고친 뒤:

| as_of | 가격 | BCS | 문서 기록값 |
|---|---:|---:|---:|
| 2018-12-15 | $3,185 | **−86.6** | −86.6 ✓ |
| 2021-11-10 | $64,756 | **+52.0** | +52.0 ✓ |

문서에 적힌 그날의 값이 그대로 재현된다. 자르지 않았을 때는 둘 다 −64.2 였다.

기준일이 데이터 시작보다 앞이면 자를 수 없으므로 전체 구간으로 계산하고
**경고를 남긴다.** 조용히 빈 값을 내지 않는다.

## 2. 전환점 날짜가 다섯 곳에 흩어져 있었고, 하나가 달랐다

`TOPS`/`BOTTOMS` 가 `screen_candidate` · `robustness` · `lppls` ·
`export_viz` · `bottom_study` 에 각각 하드코딩돼 있었다. 그리고
**`bottom_study` 만 다른 날짜를 쓰고 있었다.**

어느 쪽이 맞는지 데이터로 재 봤다.

| 구간 | 실제 극값 종가일 | 값 | 도구 4곳 | bottom_study |
|---|---|---:|---|---|
| 2013 고점 | 2013-12-04 | $1,135 | 11-30 (−4일) | ✓ |
| 2017 고점 | 2017-12-16 | $19,641 | 12-17 (+1일) | ✓ |
| 2021 고점 | 2021-11-08 | $67,542 | 11-10 (+2일) | ✓ |
| 2022 저점 | 2022-11-09 | $15,758 | 11-21 (+12일) | 11-21 (+12일) |
| 2026 저점 | 2026-06-30 | $58,525 | 06-06 (−24일) | — |

**`bottom_study` 가 맞고 나머지 넷이 틀렸다.** 그리고 2022·2026 저점은
다섯 곳 전부 틀렸다.

### 여기서 중요한 것은 며칠 차이가 아니다

앞의 셋은 하루이틀 차이라 결과가 거의 안 움직인다(고점 평균 +66.6 → +66.8).
**문제는 마지막 저점이다.**

| | 고른 날짜 (2026-06-06) | 잰 날짜 (2026-06-30) |
|---|---:|---:|
| 그날 가격 | $60,772 | **$58,525** |
| 그날 BCS | −73.7 | −67.8 |
| 저점 네 곳 평균 | −85.6 | **−84.1** |
| 저점 네 곳 σ | 8.7 | **10.8** |
| 고점–저점 빈 공간 | 124점 | **118점** |

**고른 날짜가 잰 날짜보다 결과를 좋아 보이게 했다.** σ 가 작고 빈 공간이
넓게 나온다.

의도한 것은 아니다 — 2026-06-06 은 아마 그 시점에 "국소 저점"으로 보였던
날일 것이다. 하지만 [docs/14](14-과적합-노출도.md)가 경고한 형태가 정확히
이것이다. **결과를 평가하는 기준 자체를 사람이 고르면, 고르는 순간 편향이
들어간다.** 자유도 269개를 세고 교차자산으로 표본을 늘려 놓고서, 성적표의
채점 기준을 손으로 고르고 있었다.

### 그래서 날짜를 데이터에서 뽑게 했다

`src/btc_core/cycles.py` 를 만들었다. 사람이 정하는 것은 **탐색 창**뿐이고,
그 안에서 최고·최저 종가일을 찾는다. 창은 **반감기에 걸어 둔다** — 반감기는
합의 규칙에 박힌 날짜라 사후 선택이 아니다.

    고점 = [반감기, 반감기+800일] 안의 최고 종가일
    저점 = [그 고점, 다음 반감기+60일] 안의 최저 종가일

`tests/test_cycles.py` 가 네 가지를 지킨다.

1. 적어 둔 날짜와 데이터에서 잰 날짜가 같을 것
2. 각 전환점이 자기 구간에서 진짜 극값일 것
3. **창을 600~1000일로 바꿔도 답이 안 바뀔 것** — 창이 답을 만들면 그것도
   고른 것이나 마찬가지다
4. **어떤 도구도 자기만의 전환점 표를 다시 만들지 않을 것** — 되돌아가는 것을
   막는다

진행 중인 사이클의 저점은 `provisional=True` 를 들고 다닌다. 더 낮은 날이
나올 수 있다는 사실이 값에 붙어 있어야 한다.

### 갱신된 성적표

| 국면 | 날짜 | BCS | 이전 값 |
|---|---|---:|---:|
| 고점 | 2013-12-04 | +74.7 | +74.6 (11-30) |
| 저점 | 2015-01-14 | −98.2 | −98.2 |
| 고점 | 2017-12-16 | +89.3 | +89.3 (12-17) |
| 저점 | 2018-12-15 | −86.6 | −86.6 |
| 고점 | 2021-11-08 | +52.4 | +52.0 (11-10) |
| 저점 | 2022-11-09 | −83.8 | −82.7 (11-21) |
| 고점 | 2025-10-06 | +50.7 | +50.7 |
| 저점 | 2026-06-30 | **−67.8** | −73.7 (06-06) |

    고점 평균 +66.8  σ 16.1        (이전 +66.6  σ 16.2)
    저점 평균 −84.1  σ 10.8        (이전 −85.3  σ  8.8)
    빈 공간  118점                 (이전 124점)
    부호 정확도 8/8                (변화 없음)

**결론은 안 바뀐다.** 여덟 번 중 한 번도 방향이 뒤집히지 않고, 고점과 저점
사이는 여전히 118점 비어 있다. 다만 **숫자가 조금 나빠졌고, 그게 정확한
숫자다.**

## 3. 그 밖에 고친 것

- **백테스트가 파생을 안 쓰고 있었다.** CLI 는 쓰는데 백테스트는 안 써서,
  같은 데이터로 돌린 두 리포트의 '현재' 값이 달랐다(−62.8 vs "MVRV —").
  이제 둘 다 파생을 적용한다.
- **계열 커버리지가 멤버 결측을 숨기는 문제가 백테스트에도 있었다.**
  마지막 날 커버리지 100% 인데 지표 2개가 빠져 BCS 가 12점 튀어 있었다.
  `Day.nmiss` 를 추가하고, 결측이 있으면 "이 점수는 반쪽이다 · 아홉 개가
  전부 산출된 마지막 날은 …" 을 함께 적는다.

## 4. 점검했고 문제 없던 것

경계 조건 25가지를 실제로 밟아 봤다. 전부 통과.

- 가격 1일치 / 전부 None / 0 / 음수 / NaN / inf
- 구간(잭나이프): 전부 결측 / 한 계열만 생존 / 점수 0 / ±1 극단
- 파생: 창세 이전 / 2100년 / 반감기 당일 / 21M 초과 안 함
- 설정: 가중치 0 / 밴드 비움 / 지표 제거 → 전부 `ConfigError`
- 불변식: BCS ∈ [−100,100], 구간이 점을 포함, 실효 가중치 합 100,
  커버리지 ∈ [0,1], 계열 점수 ∈ [−1,1]
- 결정성: 같은 입력을 두 번 돌려 같은 값
- JSON 왕복 후 정합성

시각화 쪽은 브라우저를 띄워야 보이는 사고가 두 번 났어서
[tests/test_viz.py](../tests/test_viz.py)로 막았다 — node 파서로 구문,
정적 검사로 가드 누락, 빌드 결과로 자리표시자와 외부 의존.

## 5. 남은 것

- **`Series.tail` / `slice_from` / `recent_bcs` 가 어디서도 안 쓰인다.**
  지웠다가 되살릴 일이 생기기 쉬운 종류라 남겨 뒀다. 지울 근거가 생기면 지운다.
- **2011 저점만 예외로 남았다.** 반감기 이전이라 위 규칙으로 안 잡혀서
  `bottom_study.py` 가 따로 붙인다. 저점 연구 전용이고 성적표에는 안 들어간다.
