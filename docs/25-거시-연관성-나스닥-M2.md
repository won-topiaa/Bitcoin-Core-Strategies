# 25. 거시 연관성 — 나스닥·M2 와 비트코인

2026-07-31. "나스닥·전 세계 M2 와 비트코인의 연관성을 분석·백테스트하고,
M2 는 전 세계인지 특정국인지 보자"는 요청을 실행한 기록이다.

```bash
python3 tools/fetch_macro.py --global                       # FRED 에서 받기
python3 tools/macro_correlation.py --macro data/macro.csv   # 분석
python3 tools/macro_correlation.py --self-test              # 로직 검증
```

---

## 1. 데이터 — 이 환경에서는 못 받는다

거시 데이터의 무료 표준 출처는 **FRED**(미국 연준, 키 불필요)다. 나스닥
종합(NASDAQCOM)과 미국 M2(M2SL) 를 CSV 로 그냥 준다. 전 세계 M2 는 주요국
M2 를 달러로 환산해 더한다.

그런데 **이 에이전트 환경의 프록시가 fred.stlouisfed.org 를 정책상 403 으로
막는다.** Yahoo·Stooq 도 같다. CoinMetrics(우리가 쓰는 무료 소스)는 암호화폐
전용이라 거시가 없다. 그래서 **이 세션에서는 실제 나스닥·M2 숫자를 못 받는다.**

정책 차단은 되돌릴 수 없으니(재시도 금지), 대신 **분석 파이프라인을 완성해
두었다.** FRED 가 열린 곳에서 `fetch_macro.py` 로 `data/macro.csv` 를 만들면,
분석은 이 환경에서도 그대로 돈다. 오프라인 우선 설계는 이 시스템 전체의
방식이기도 하다.

## 2. 무엇을 재는가 — 레벨이 아니라 변화율

세 시계열(나스닥·M2·비트코인)은 전부 장기 우상향이다. **레벨끼리 상관을 재면
"같이 올랐다"만 나온다** — 허위 상관이다. 그래서 전부 변화율로 잰다.

- **나스닥** — 주간 로그수익률의 상관. "요즘 얼마나 같이 움직이나."
- **M2** — 전년비 증가율의 **선행/후행 스캔.** BTC 수익률을 M2 증가율보다
  k개월 뒤로 놓고 상관이 최대가 되는 k 를 찾는다 = "M2 가 BTC 를 k개월 앞선다."

이 로직이 맞는지는 합성 데이터로 못 박았다 — M2 를 BTC 보다 **정확히 3개월
앞서게** 심어 두면 스캔이 3개월을 찾아낸다([tests/test_macro.py], `--self-test`).

## 3. 알려진 결과 (숫자는 데이터가 열리면 확정)

실제 데이터를 못 받았으니 아래는 **문헌·상식 수준의 정리**다. 도구가 준비돼
있으니 데이터가 들어오면 바로 검증된다.

### 나스닥 ↔ 비트코인

- **2020년 이전엔 거의 무상관.** 비트코인은 크립토 자체 사이클로 움직였고,
  주간 수익률 상관이 0 근처였다.
- **2020년 코로나 이후 급등.** 기관 편입·거시 유동성 국면에서 비트코인이
  "고베타 위험자산"으로 취급되며 나스닥과 30~90일 상관이 **0.4~0.6** 까지 올랐다.
- **국면 의존적이다.** 거시 스트레스(금리·침체 공포) 때 함께 급락하며 상관이
  튀고, 크립토 고유 랠리(반감기 후 등) 때는 다시 벌어진다. **고정 상수가
  아니다** — 그래서 우리 시스템은 이걸 점수(BCS)에 안 넣고 거시 축(LRS)의
  참고로만 둔다.

### 전 세계 M2 ↔ 비트코인

- **전 세계 M2 가 비트코인을 대략 10~13주(2.5~3개월) 앞선다**는 관계가 시각적으로
  강하게 보인다(Raoul Pal 등이 대중화). 통화가 풀리면 위험자산이 나중에 따라
  오른다는 가설과 맞는다.
- **미국 M2 단독보다 전 세계 M2 집계가 더 잘 맞는 편이다.** 비트코인 유동성은
  국경이 없어서, 미국만 보면 중국·유럽·일본의 완화/긴축을 놓친다. 특히 **중국
  M2** 가 집계에 들어가면 설명력이 올라간다는 관찰이 흔하다.
- **그러나 통계적으로 약하다.** (a) 통화 사이클 표본이 두세 번뿐이고,
  (b) 2020~2021 유동성 급증 **한 번**이 상관을 통째로 끌어올린다. 그 한 번을
  빼면 관계가 크게 약해진다. (c) "선행 몇 주"는 표본 외에서 불안정하다.

### "전 세계 vs 특정국" — 도구가 답하는 방식

`macro_correlation.py` 는 `m2_us`·`m2_global`·`m2_cn`·`m2_eu`·… 각 열마다 선행/후행
스캔을 돌려 **최고 상관과 그때의 선행 개월**을 나란히 출력한다. 어느 M2 가 더
잘 설명하는지가 표 하나로 나온다. 예상은 `m2_global` ≳ `m2_cn` > `m2_us` 이지만,
**숫자로 확인하기 전까지는 예상일 뿐**이다.

## 4. 그래서 시스템에 어떻게 반영하나

이미 자리가 있다. **LRS(유동성 레짐 축)** 의 구성요소로 `global_m2_yoy` 와
`dxy` 가 설정에 들어 있다([config/strategy.yaml] `lrs.components`). LRS 는 BCS
와 **분리된 축**이고, 실행의 *방향*이 아니라 *크기*만 0.75~1.25배로 조절한다.

이 분석이 그 설계를 뒷받침한다 — 거시 관계는 **국면 의존적이고 표본이 작아**
방향 신호로 쓰기엔 위험하지만, "유동성 순풍일 때 조금 더, 역풍일 때 조금 덜"
정도의 크기 조절에는 쓸 만하다. M2 는 지금 `manual` 입력이라, `fetch_macro.py`
가 그 값을 자동으로 채우도록 잇는 것이 다음 단계다(데이터가 열리면).

## 5. 남긴 것

| 파일 | 하는 일 |
|---|---|
| `tools/fetch_macro.py` | FRED 에서 나스닥·미국 M2·(선택)전 세계 M2 를 받는다. 403 이면 명확히 안내 |
| `tools/macro_correlation.py` | 나스닥 수익률 상관 + M2 선행/후행 스캔. `--self-test` 내장 |
| `tests/test_macro.py` | 심어 둔 선행·상관을 되찾는지 등 7개 |

FRED 가 열린 환경에서 두 줄이면 실제 숫자가 나온다.
