## 이것이 무엇이고, 무엇이 아닌가

**이 시스템은 "지금 사라 / 지금 팔아라"를 말하는 도구가 아니다.**

하는 일은 하나다 — **지금 가격이 과거 16년 데이터에 비교해 저점 부근인지
고점 부근인지를, 오늘 기준으로 다시 세워 보여주는 것.** BCS 는 예측값이
아니라 **위치값**이다. −64.2 는 "떨어질 것이다"가 아니라 "자기 4년 범위에서
저평가 쪽 극단에 있다"는 뜻이다.

그래서 평가 기준도 수익률이 아니다. **네 번의 사이클 고점에서 실제로 고점
쪽을 가리켰는가, 네 번의 저점에서 저점 쪽을 가리켰는가**가 이 지표의 성적표다
([07 실측 검증](docs/07-실측-검증.md), [15 교차자산 검증](docs/15-교차자산-검증.md)).

사다리·DCA·히스테리시스가 붙어 있는 것은 그 위치값을 **행동으로 옮길 때
한 번에 다 하지 않게** 만들려는 안전장치다. 위치 판정이 본체이고 실행 규칙은
그 위에 얹힌 껍데기다. 위치가 틀리면 껍데기는 의미가 없고, 위치가 맞아도
껍데기는 언제든 각자의 사정에 맞게 바꿔도 된다.

정규화가 **퍼센타일 전용**인 것도 이 목적 때문이다. 고정 임계는 "절대적으로
비싸다"를 말하려 하고, 퍼센타일은 늘 **"자기 4년 범위 안 어디쯤"** 만 말한다.
후자가 이 지표가 하려는 말이다.

## 한 문단 요약

원문 12개 지표를 계산 재료 기준으로 다시 세면 실제 정보원은 4가지뿐이다.
가격 계열 4종(Pi Cycle, Golden Ratio, 200주 MA, 2년 MA)은 전부 "가격 ÷ 이동평균"의
변형이고, MVRV Z와 NUPL은 분자가 같다. 이 중복을 걷어내고 계열별 가중치를 매겨
**BCS(사이클 위치, −100 ~ +100)** 하나로 압축했다. 거시 지표는 여기에 더하지 않고
**LRS(유동성 레짐)**라는 별도 축으로 분리해 실행의 *방향*이 아니라 *크기*만
조절하게 했다. 그리고 어떤 극단값이 나와도 한 번에 전부 사고팔지 않도록,
14일 간격의 5단 분할 사다리와 되돌림 방지 장치를 붙였다.

## 왜 이렇게 만들었나

원문 6.1이 이렇게 경고한다.

> MVRV Z-Score와 NUPL처럼 계산 재료가 거의 같은 지표 두 개가 같은 신호를 낸다고
> 해서 그것을 "두 번의 확인"으로 세면 안 됩니다.

이 경고를 끝까지 밀어붙이면 12개 목록이 이렇게 접힌다.

| 계열 | 실제로 재는 것 | 원문 지표 | BCS 지분 |
|---|---|---|---:|
| **원가 대비** | 시가총액을 무엇으로 나누는가 | MVRV Z-Score, NUPL, 서멀캡 배수 | **40%** |
| **평균가 대비** | 가격 ÷ 어떤 기간의 평균가 | Pi Cycle, Golden Ratio, 200주 MA, 2년 MA | **33%** |
| **채굴 상황** | 코인을 만들어 내는 쪽 사정 | Puell Multiple, Hash Ribbons | **27%** |

원문의 '코인 나이 분포'(RHODL / Reserve Risk / LTH 배수)는 **뺐다.** 공개
데이터로 재현이 안 되고, 그래서 16년 백테스트에 **한 번도 들어간 적이
없었다** — 검증된 전략은 처음부터 3계열이었다.
근거: [10 보유자 계열 제거](docs/10-보유자-계열-제거.md).

'원가 대비' 계열은 집계가 `max_abs` 라 **그때그때 가장 극단인 지표 하나가
40% 를 혼자 끌고 간다.** MVRV Z 하나만 0 → +1 로 가면 나머지가 전부 중립이어도
BCS 가 +40 이 되어 구간이 '중간'에서 '비싼 편'으로 넘어간다.

**즉 지표 하나로 밴드와 DCA 는 바뀔 수 있다.** 바뀌지 않는 것은 사다리 실행이다 —
분배·매집 계단은 아래 합의 게이트를 통과해야만 열리고, 계열 하나로는 절대
통과하지 못한다.

거기에 원문 6.1을 기계적으로 강제하는 **합의 게이트**를 걸었다.

> 3계열 중 2개 이상이 같은 방향, **그중 최소 1개는 '평균가 대비'가 아닐 것**

가격 이동평균 4종이 강세장 후반에 한꺼번에 붉어지는 착시 — 실전에서 가장 흔한
오판 — 를 구조적으로 차단한다. 가격은 한 계열뿐이라 **혼자서는 2를 채울 수
없고**, 따라서 단독 통과가 산술적으로 불가능하다.

## 설치와 첫 실행

```bash
pip install -r requirements.txt
pip install -e .                    # btc-core 명령 등록 (선택)
```

설치 없이 바로 돌려보려면 동봉된 합성 데이터를 쓴다.

```bash
python3 -m btc_core.cli score \
  --csv data/sample_synthetic.csv \
  --manual data/manual_input.example.yaml \
  --as-of 2025-02-12
```

> `data/sample_synthetic.csv`는 **합성 데이터**다. 실제 비트코인 시세가 아니다.
> 엔진이 어떻게 동작하는지 보기 위한 것이고 그 이상의 의미는 없다.

실전 데이터로 돌리려면:

```bash
python3 tools/probe_sources.py             # 이 환경에서 무엇이 열려 있는지 먼저 확인
btc-core fetch --save data/market.csv      # CoinMetrics 커뮤니티 API (키 불필요)
btc-core init                              # 수동 입력 템플릿 생성
# data/manual_input.yaml 을 BM Pro 차트 보고 채운다
btc-core score --csv data/market.csv
```

두 번째부터는 `refresh_data.py` 로 **증분 갱신**한다. `fetch` 는 파일을 통째로
갈아 끼우지만, 이쪽은 검증을 통과한 뒤에만 쓰고 **이미 있는 값을 빈 값으로
덮지 않는다.**

```bash
python3 tools/refresh_data.py --check      # 지금 데이터가 며칠 전 것인가
python3 tools/refresh_data.py --dry-run    # 무엇이 바뀌는지만
python3 tools/refresh_data.py --build      # 받아서 병합하고 사이트까지
```

겹치는 구간의 가격이 2% 넘게 다르면 다른 자산·다른 단위를 받은 것으로 보고
**아무것도 쓰지 않고 멈춘다.** `.github/workflows/refresh-data.yml` 이 매일
02:20 UTC 에 이 과정을 돌리고, **테스트를 통과한 뒤에만** 페이지를 다시 굽는다
([22](docs/22-자동갱신과-두-언어.md)).

### 공개 데이터만으로 돈다 — 외부 필수 시계열은 2개다

지표 9개에 쓰는 시계열은 7개인데, **4개는 API 없이 계산된다.** 비트코인의
발행 스케줄이 합의 규칙에 박혀 있기 때문이다.

    price          외부 필수    대체 불가
    realized_cap   외부 필수    체인 전체를 훑어야 나온다 — 계산 불가
    supply         계산         반감기 스케줄
    market_cap     계산         price × supply
    issuance_btc   계산         supply 의 일간 차분
    issuance_usd   계산         issuance_btc × price
    hashrate       선택         없으면 Hash Ribbons 하나만 결측
    active_addr    선택         없으면 mcap_per_active 하나만 결측

가격과 실현시총만 담은 CSV 로 돌리면 커버리지 33% → **100%**, BCS −59.0 →
**−64.4** 가 된다. 실측 전체로 계산한 값은 −64.2 다. 파생을 끄면(`--no-derive`)
밸류에이션·공급 계열이 통째로 빠지고 **가격 이동평균만으로 사이클 위치를
판정하는 상태**가 되므로, 파생은 그 상태 자체를 없애는 장치다.

파생 정확도는 2015년 이후 평균 0.079%, 2020년 이후 0.011% 다. 사이클 전환점
8곳에서 실측 BCS 와의 평균 절대차가 **1.16점**이고 부호가 뒤집히는 곳은 없다.
자세한 내용과 소스별 대안 목록: [18 무료 데이터 경로](docs/18-무료-데이터-경로.md).

**BCS 가 점이 아니라 구간이다.** `-76 ~ -55` 는 지표를 하나씩 빼고 다시 계산한
값들의 범위이고, 마지막 줄이 어느 지표가 그 양 끝을 만드는지 알려준다.
구간이 밴드 경계를 걸치면 "두 국면 사이"로 쓰고, **실행은 점수 기준**임을
따로 적는다 — 표시와 실행을 섞지 않는다.

`--format markdown`으로 저널에 붙일 문서를, `--format json`으로 다른 도구에
넘길 데이터를 뽑을 수 있다.

### 시각화 — 페이지 네 장

```bash
python3 tools/build_viz.py --csv data/market.csv     # viz/site/ 에 네 장
python3 tools/build_viz.py --csv data/market.csv \
    --index-url https://... --verify-url https://... \
    --rules-url https://... --liquidity-url https://...
```

| 페이지 | 내용 | 높이 |
|---|---|---:|
| `index.html` | 계기판 · 변화량 · **지표 9개 요약** · 16년 이력 | 3,483px |
| `verify.html` | 전환점 성적표 · 계산 방법 · 범위가 나오는 이유 | 4,788px |
| `rules.html` | 실행 규칙 · 한계 · 데이터 출처 · 자동 갱신 | 4,306px |
| `liquidity.html` | **04 유동성** — 중국 M2 선행 겹쳐보기 · 왜 크기에만 쓰나 | 1,900px |

**한 장에 다 넣지 않는다.** 처음에 한 장이었을 때 7,500px 였고, 그러니까
"무엇을 봐야 하는가"가 사라졌다. 네 장으로 나누고 각 장 맨 위에 이동 막대를 뒀다.

첫 화면의 큰 숫자(`−63 ~ −60`) 바로 밑에 **사람 말로 옮긴 한 줄**이 붙는다 —
"지난 16년을 통틀어 **아래에서 14% 지점**입니다. 5,856일 가운데 오늘보다 싼
쪽이었던 날이 14% 뿐이라는 뜻입니다." 새로 정한 숫자는 없고, 오늘 점수보다
낮았던 날을 **일 단위 전체**에서 센 비율일 뿐이다(추린 시계열로 세면 최근 400일이
과대 대표돼 조용히 틀린다 — 테스트로 막아 뒀다).

16년 그림에는 **오늘 수준에 가로 점선**이 그어져 있다. 선이 지나가는 곳이 전부
지금과 같은 자리였던 때라서, "과거에 이런 적이 몇 번 있었고 그 뒤에 어떻게
됐나"가 그림 하나로 읽힌다.

차트는 **키보드로도 짚을 수 있다.** 탭으로 잡고 `←` `→` 로 하루씩, `Shift`·
`PageUp/Down` 으로 크게, `Home`·`End` 로 처음·끝, `Esc` 로 해제한다. 처음
들어오면 오늘부터 시작한다 — 왼쪽 끝에서 시작하면 지금에 닿는 데 5,000번을
눌러야 한다. 툴팁은 낭독기가 읽지 않으므로 같은 내용을 `aria-live` 로 따로 준다.

**지표 9개 요약**이 첫 장의 핵심이다. 아홉 개를 싼 쪽부터 정렬해 각각의 현재값,
"최근 4년 중 몇 %", **직전에 이만큼 극단이었던 시기**를 보여준다. 점수 하나가
어디서 왔는지가 이 하나로 보인다. **720px 아래에서는 표 대신 카드**로 바뀐다 —
가로로 잘린 표는 핵심을 못 보는 화면이 된다.

`@media print` 가 있어서 인쇄하면 접힌 설명이 전부 펴지고 이동 막대가 사라진다.

머리띠에 버튼이 두 개 있다 — **한국어/English** 와 **밝게/어둡게**. 선택은
기억되고, 처음 오는 사람에게는 브라우저·OS 설정을 따른다. 테마는 `<style>` 바로
뒤 인라인 스크립트가 첫 페인트 전에 적용한다 — 본 스크립트에서 하면 흰 화면이
한 번 번쩍인다.

#### 조각을 합쳐 굽는다

    viz/_head.html        스타일 (네 장 공용)
    viz/_nav.html         머리띠 — 페이지 이동 + 언어·테마 버튼
    viz/_script.html      차트 엔진 (네 장 공용, 없는 요소는 건너뛴다)
    viz/_i18n.html        본문 산문의 영어 판 (data-t 키와 1:1)
    viz/*.body.html       페이지별 본문 넷

CSS·JS·데이터를 한 파일에 굽는 자기완결 HTML 이다. **외부 요청이 하나도 없다** —
요청이 막힌 환경에서 빈 화면이 나오면 공개 데이터로 돌아가는 시스템에서 그건
"안 보인다"와 같다. `tests/test_viz.py` 가 그것을 포함해 지킨다:
node 파서로 구문, 정적 검사로 가드 누락, 빌드 결과로 자리표시자와 외부 의존.

두 언어의 유일한 위험은 **어긋남**이다. 지표를 추가하고 영어를 잊으면 영어 화면
한가운데에 한국어가 남고, 그건 번역하지 않은 화면보다 나쁘다. `tests/test_i18n.py`
가 세 곳의 키 집합을 **양방향으로** 대조한다 — 본문 `data-t` ↔ `_i18n.html`,
`TX.ko` ↔ `TX.en`, `strategy.yaml` ↔ `strings.en.yaml`. 빠진 것도 남는 것도
실패다 ([22](docs/22-자동갱신과-두-언어.md)).

설명 문구는 `config/strategy.yaml` 의 `explain` / `explain_long` 이 소유한다 —
페이지에 따로 적어 두면 지표를 고칠 때 둘이 어긋나고, **어긋난 설명은 없는
설명보다 나쁘다.** 같은 문구가 `btc-core explain <지표>` 로도 나온다.

## 실행 규칙 요약

**자산을 세 통으로 나눈다.** 코어 40%(어떤 신호에도 팔지 않음) / 트레이딩 60% /
예비 현금(정기 DCA와 별개 예산).

| BCS | 구간 | 태도 | DCA 배수 |
|---:|---|---|---:|
| +70 ~ +100 | 천장권 | 나눠 팔기 가속 | 0.0 |
| +45 ~ +70 | 고점 부근 | 나눠 팔기 시작 | 0.0 |
| +20 ~ +45 | 비싼 편 | 새로 사지 않고 적립만 | 0.5 |
| −20 ~ +20 | 중간 | 평소대로 적립 | 1.0 |
| −45 ~ −20 | 싼 편 | 적립액 늘리기 | 1.5 |
| −70 ~ −45 | 저점 부근 | 예비 현금 넣기 시작 | 2.0 |
| −100 ~ −70 | 바닥권 | 예비 현금 집중 투입 | 2.5 |

구간 이름에 '항복'·'도취' 같은 심리 용어를 쓰지 않는다. **이 지표는 사람들의
감정을 재는 게 아니라 지금 가격이 과거 대비 어디쯤인지를 잰다.** 화면에 뜨는
이름이 그 사실과 어긋나면 읽는 사람이 다른 것을 기대하게 된다.

**분배 사다리** +45 / +55 / +65 / +75 / +85 에서 각 10 / 10 / 10 / 15 / 15%
(누적 60% — 코어 40%와 정확히 맞물린다)

**매집 사다리** −30 / −45 / −58 / −70 / −82 에서 예비현금의 15 / 20 / 20 / 20 / 25%

**히스테리시스** 3일 연속 확정 · 계단 간 14일 · **반대편 구간(∓20)을 방문해야
재무장**. BCS가 +90으로 튀어도 5계단이 한꺼번에 실행되지 않는다. 사다리를 다
오르는 데 최소 8주가 걸린다. 재무장되더라도 한 사이클 누적은 60%를 못 넘는다.

**LRS 조정** 트랜치 크기를 0.75 ~ 1.25배 사이에서만 조절한다. 매수를 매도로
바꾸지 못한다.

**저점 프로파일** 과거 사이클 저점 네 곳의 공통 조건 6가지와 현재 상태를 대조해
보여준다. **점수에는 들어가지 않는다** — 임계값이 그 저점들을 보고 정해진 것이라
순환논리 위험이 있고, 절반은 이미 다른 지표가 세고 있기 때문이다. BCS가 "싸다"고
할 때 "역사적 바닥과 같은 상태인가"는 다른 질문이라 함께 본다 —
[09 저점 프로파일](docs/09-저점-프로파일.md).

## 전략을 고치는 법

임계값은 코드가 아니라 `config/strategy.yaml`에 있다. 가중치, 앵커, 사다리 계단,
히스테리시스 파라미터를 전부 거기서 고친다.

설정을 읽을 때마다 아홉 가지를 검사한다 — 가중치 합 100, 밴드가 −100~100을 빈틈
없이 덮는지, 매도 사다리 누적이 코어 지분을 침범하지 않는지 등. 하나라도 어긋나면
프로그램이 시작하지 않는다. 가중치를 손으로 고치다 합이 97이 되는 실수는 언젠가
반드시 일어나고, 그때 조용히 잘못된 점수가 나오는 것보다 멈추는 편이 낫다.

그 검사는 **한 항목 안의 형식**만 본다. **항목들 사이의 관계**는 별도 도구가 본다.

```bash
python3 tools/audit_config.py
```

커버리지 하한 때문에 도달 불가능한 계열 조합이 있는지, 저점 프로파일 조건 중
수학적으로 같은 것이 있는지, 합의 게이트가 데이터가 적을수록 오히려 엄해지지는
않는지를 확인한다. 값을 하나 고칠 때 조용히 깨지는 것들이라 설정을 손볼 때마다
돌리는 편이 좋다.

## 알아둘 것

- **BCS 점수 지표는 전부 자동 계산된다.** 거시 축(LRS)도 M2 임펄스는 중국 M2에서
  자동 계산되고(`fetch_macro.py`), **수동 입력에 남은 것은 LRS 3종(DXY·연준·ETF)과
  바닥선 2개(LTH 실현가격, CVDD)뿐이다** — 바닥선 4개 중 2개(200주 MA, 실현가격)는
  자동 계산된다. 어느 쪽도 방향 판단을 바꾸지 않는다 — LRS 는 실행 '크기'만 조절하고,
  바닥선은 점수가 아니라 참고 가격이다. 수동 3종은 45일 지나면 경고, 120일 지나면
  자동 결측 처리된다.
- **BCS 는 점이 아니라 구간으로 표시된다.** 지표를 하나씩 빼고 다시 계산한
  값들의 범위이고, **새 파라미터가 하나도 없다** — 폭은 데이터가 정한다.
  16년 중위 폭이 **16.6점**이고, 구간이 한 밴드 안에 온전히 들어오는 날은
  **45.8%** 뿐이다. 절반이 조금 안 되는 날만 국면을 하나로 말할 수 있다는 뜻이다.
  앵커를 ±50% 왜곡하는 전혀 다른 실험도 ±16점을 냈다 — 두 방법이 같은 크기를
  가리키면 그게 이 시스템의 실제 해상도다
  ([19 BCS 구간 표시](docs/19-BCS-구간-표시.md), [14 과적합 노출도](docs/14-과적합-노출도.md)).
- **구간은 표시 전용이다.** 밴드·사다리·DCA 는 점수 하나로만 결정된다.
  구간으로 게이트를 걸면 "구간이 걸치면 보류" 같은 새 규칙이 생기고 그건
  자유도를 늘리는 일이다. 테스트로 못 박아 뒀다.
- **조정 가능한 숫자가 269개인데 유효 표본은 사이클 4개다.** 비율로는 67:1 로
  변명할 수 없다. 그래서 `tools/robustness.py` 로 "그 숫자들이 실제로 결론을
  떠받치는가"를 따로 재고, 못 믿을 숫자(프로파일 임계)는 점수 밖으로 뺐다.
  고정 앵커는 실제로 사이클을 넘지 못한다. **그래서 기본 정규화를 퍼센타일
  전용으로 바꿨다** — 근거는 비트코인 백테스트가 아니라 라이트코인·이더리움
  전환점 21곳의 표본 외 검증이다(포착률 76.2% vs 앵커 66.7%,
  [15 교차자산 검증](docs/15-교차자산-검증.md)).
- **앵커는 2025 사이클 실측에 맞춰져 있다.** 16년치로 검증하면서 상단 앵커를
  전면 재조정했다([07 실측 검증](docs/07-실측-검증.md)). 다음 사이클의 고점이
  더 낮으면 또 못 잡는다. 감쇠가 계속된다는 데 베팅하지 않고 관측된 마지막
  사이클에 맞췄을 뿐이다.
- **가중치와 사다리 트리거 자체는 여전히 백테스트로 최적화하지 않았다.** 표본
  사이클이 네 번뿐인 상황에서 최적화하면 과적합이 된다. 논리로 정하고
  [반증 조건](docs/06-한계와-반증조건.md#3-반증-조건)을 붙이는 쪽을 택했다.
- **'코인 나이 분포'라는 독립 축이 없다.** 보유자 행동 계열을 뺀 대가다.
  남은 3계열은 원가·가격·채굴을 보는데, 코인이 얼마나 오래 잠들어 있는지는
  아무도 보지 않는다. CoinMetrics 커뮤니티 티어에는 HODL 웨이브도 휴면일수도
  SOPR 도 없다(BTC 지표 31개 전수 확인). 자동화하려면 구독 데이터가 필요하다 —
  [10 보유자 계열 제거](docs/10-보유자-계열-제거.md).
- **밸류에이션 하나가 40%다.** `max_abs` 집계라 그 안의 지표 하나가 40% 를
  혼자 끌고 간다. 16년 백테스트 내내 실효 가중치가 이미 40 이었으므로 새로
  생긴 위험은 아니지만, 이제는 설정에도 그렇게 적혀 있다.
- **계열이 생각만큼 독립이 아니다.** 합의 게이트는 '계산 원리가 다른 계열
  2개가 같은 방향'을 요구하는데, 실제로 재보니 밸류에이션↔가격 ρ **+0.83**
  이다. Puell 은 더 심해서 GRM 과 **+0.89** 였다 — 반감기 사이 발행량이 약분돼
  사실상 `가격 ÷ MA365(가격)` 이었다. 기준선을 반감기 너머(1460일)로 옮겨
  +0.495 로 낮췄지만 밸류에이션↔가격은 그대로다. INV-5 로 못 박았다 —
  [13 계열 독립성 점검](docs/13-계열-독립성-점검.md).
- **고점 탐지력이 사이클마다 약해지고 있다.** 네 고점에서의 4년 퍼센타일이
  Puell +0.99 → +1.00 → +0.46 → −0.00, Pi Cycle +0.47 → +0.86 → −0.02 → −0.00
  으로 무너졌다. 대체 후보 8개를 검정했지만 점수 지표로 채택할 만한 것은
  없었고, 대신 표시 전용 **고점 프로파일**을 만들었다 —
  [11 지표 발굴 2차](docs/11-지표-발굴-2차.md).
- **지표 사이트 466개를 전수 조사했고 새로 채택한 것은 없다.** 59%는 공개
  데이터로 원천 시계열을 만들 수 없고(UTXO 나이 분포·CDD·SOPR 계열), 계산
  가능한 것 중 심사한 9개는 전부 기각됐다 — Top Cap, Delta Top, Delta Cap,
  RSI-14, MACD, 볼린저 %B 같은 유명한 것들이 여기 포함된다.
  구독을 하나만 산다면 온체인이다(168건, 61% 해제) —
  [16 지표 전수조사](docs/16-지표-전수조사.md).
- **유명한 지표는 대개 이미 들어 있다.** 미심사 후보 13건을 추가로 검정했더니
  8건이 상관으로 걸렸다 — Ahr999(+0.92), Bitcoin Profitable Days(+0.97),
  Mayer(+0.91), Pi Cycle Bottom(+0.90), Sharpe(+0.92), AASI(+0.88),
  Investor Price(+0.94). 공개적으로 구할 수 있는 재료가 6개뿐이라 조합만 다를 뿐
  같은 정보를 본다. **새 지표를 찾는 일의 기대수익은 낮다** —
  [17 미심사 후보 검정](docs/17-미심사-후보-검정.md).
- **내 검정 관문에도 구멍이 있었다.** MVRV 모멘텀이 전환점 8곳을 깨끗하게
  통과했는데 십분위가 단조 증가(ρ +0.23)였다 — 사이클 위치가 아니라 모멘텀을
  재고 있었다. **전환점 8곳은 표본이 8이다.** 전 표본을 보는 검사와 어긋날 때
  그것 자체를 실패로 세는 게이트를 추가했다.
- **실현시총이 유일한 단일 장애점이다.** 나머지는 전부 계산되거나 대안이
  있는데, 실현시총만 체인 전체를 훑어야 나오고 공개 경로가 2개뿐이다
  (CoinMetrics 역산 / BGeometrics). 둘 다 막히면 밸류에이션 계열 40 중
  서멀캡만 남는다 — [18 무료 데이터 경로](docs/18-무료-데이터-경로.md).
- **고점 탐지 실패는 지표 선택의 문제가 아니다.** 가장 유망하던 미검정 후보
  LPPLS 를 실제로 적합시켜 봤다. 방향은 8/8 맞았지만 **"최근 1년 수익률 부호"라는
  한 줄짜리 기준선도 8/8** 이었다. 그리고 네 고점에서 달성 가능한 최소 오차가
  0.09 ~ 0.32 로 3.5배 차이라 한 임계로 네 사이클을 다룰 수 없었다.
  **2013년 고점과 2025년 고점은 구조 자체가 다르다** — 지표를 바꿔서 해결할
  문제가 아니라는 뜻이다 ([20 LPPLS 검정](docs/20-LPPLS-검정.md)).
- **거래소 API 연동이 없다.** 의도적이다. 실행 버튼은 사람이 누른다.
