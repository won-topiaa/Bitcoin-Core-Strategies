# Bitcoin Core Strategies

**BCS / LRS — 나만의 비트코인 핵심 지표 및 전략**

Bitcoin Magazine Pro의 사이클 타이밍 지표 12개에서 핵심을 뽑아, **서로 독립적인
4개 계열 + 1개 거시 축 + 3개 바닥선**으로 재구성한 판단 시스템과 그 실행 엔진.

---

## 한 문단 요약

원문 12개 지표를 계산 재료 기준으로 다시 세면 실제 정보원은 4가지뿐이다.
가격 계열 4종(Pi Cycle, Golden Ratio, 200주 MA, 2년 MA)은 전부 "가격 ÷ 이동평균"의
변형이고, MVRV Z와 NUPL은 분자가 같다. 이 중복을 걷어내고 계열별 가중치를 매겨
**BCS(사이클 위치, −100 ~ +100)** 하나로 압축했다. 거시 지표는 여기에 더하지 않고
**LRS(유동성 레짐)**라는 별도 축으로 분리해 실행의 *방향*이 아니라 *크기*만
조절하게 했다. 그리고 어떤 극단값이 나와도 한 번에 전부 사고팔지 않도록,
14일 간격의 5단 분할 사다리와 되돌림 방지 장치를 붙였다.

---

## 왜 이렇게 만들었나

원문 6.1이 이렇게 경고한다.

> MVRV Z-Score와 NUPL처럼 계산 재료가 거의 같은 지표 두 개가 같은 신호를 낸다고
> 해서 그것을 "두 번의 확인"으로 세면 안 됩니다.

이 경고를 끝까지 밀어붙이면 12개 목록이 이렇게 접힌다.

| 실제 정보원 | 원문 지표 | BCS 지분 |
|---|---|---:|
| 시장 전체의 미실현 손익 | MVRV Z-Score, NUPL, 서멀캡 배수 | **30%** |
| 코인의 나이 분포 | RHODL, Reserve Risk, LTH 실현가격 | **25%** |
| 가격 ÷ 이동평균 | Pi Cycle, Golden Ratio, 200주 MA, 2년 MA | **25%** |
| 채굴 부문 | Puell Multiple, Hash Ribbons | **20%** |

**어떤 단일 지표도 최종 지분 30%를 넘지 못한다.** 밴드 하나를 넘기려면 보통
25점이 필요하므로, 지표 하나가 극단으로 가는 것만으로는 행동이 바뀌지 않는다.

거기에 원문 6.1을 기계적으로 강제하는 **합의 게이트**를 걸었다.

> 4계열 중 3개 이상이 같은 방향, **그중 최소 2개는 가격 계열이 아닐 것**

가격 이동평균 4종이 강세장 후반에 한꺼번에 붉어지는 착시 — 실전에서 가장 흔한
오판 — 를 구조적으로 차단한다.

## 설치와 첫 실행

```bash
pip install -r requirements.txt
pip install -e .                    # btc-core 명령 등록 (선택)
```

설치 없이 바로 돌려보려면 동봉된 합성 데이터를 쓴다.

```bash
python3 -m btc_core.cli score \
  --csv data/sample_synthetic.csv \
  --manual data/manual_input.example.yaml \
  --as-of 2025-02-12
```

> `data/sample_synthetic.csv`는 **합성 데이터**다. 실제 비트코인 시세가 아니다.
> 엔진이 어떻게 동작하는지 보기 위한 것이고 그 이상의 의미는 없다.

실전 데이터로 돌리려면:

```bash
btc-core fetch --save data/market.csv     # CoinMetrics 커뮤니티 API (키 불필요)
btc-core init                              # 수동 입력 템플릿 생성
# data/manual_input.yaml 을 BM Pro 차트 보고 채운다
btc-core score --csv data/market.csv
```

## 실행 규칙 요약

**자산을 세 통으로 나눈다.** 코어 40%(어떤 신호에도 팔지 않음) / 트레이딩 60% /
예비 현금(정기 DCA와 별개 예산).

| BCS | 밴드 | 태도 | DCA 배수 |
|---:|---|---|---:|
| +70 ~ +100 | 극단 과열 | 분배 가속 | 0.0 |
| +45 ~ +70 | 과열 | 분배 시작 | 0.0 |
| +20 ~ +45 | 상단 중립 | 신규 매수 중단 | 0.5 |
| −20 ~ +20 | 중립 | 기본 DCA 유지 | 1.0 |
| −45 ~ −20 | 저평가 | DCA 증액 | 1.5 |
| −70 ~ −45 | 깊은 저평가 | 예비현금 투입 시작 | 2.0 |
| −100 ~ −70 | 극단 항복 | 예비현금 집중 투입 | 2.5 |

**분배 사다리** +45 / +55 / +65 / +75 / +85 에서 각 10 / 10 / 10 / 15 / 15%
(누적 60% — 코어 40%와 정확히 맞물린다)

**매집 사다리** −30 / −45 / −58 / −70 / −82 에서 예비현금의 15 / 20 / 20 / 20 / 25%

**히스테리시스** 3일 연속 확정 · 계단 간 14일 · **반대편 구간(∓20)을 방문해야
재무장**. BCS가 +90으로 튀어도 5계단이 한꺼번에 실행되지 않는다. 사다리를 다
오르는 데 최소 8주가 걸린다. 재무장되더라도 한 사이클 누적은 60%를 못 넘는다.

**LRS 조정** 트랜치 크기를 0.75 ~ 1.25배 사이에서만 조절한다. 매수를 매도로
바꾸지 못한다.

**저점 프로파일** 과거 사이클 저점 네 곳의 공통 조건 6가지와 현재 상태를 대조해
보여준다. **점수에는 들어가지 않는다** — 임계값이 그 저점들을 보고 정해진 것이라
순환논리 위험이 있고, 절반은 이미 다른 지표가 세고 있기 때문이다. BCS가 "싸다"고
할 때 "역사적 바닥과 같은 상태인가"는 다른 질문이라 함께 본다 —
[09 저점 프로파일](docs/09-저점-프로파일.md).

## 명령어

```bash
btc-core fetch   --save data/market.csv    # 시계열 받아 저장
btc-core init                              # 수동 입력 템플릿 생성
btc-core score   --csv data/market.csv     # 점수와 실행 계획
btc-core commit  --ladder distribute       # 실행한 계단 기록
btc-core history                           # 지금까지 밟은 계단
btc-core explain mvrv_z                    # 지표의 앵커 표

python3 tools/backtest.py --csv data/market.csv   # 전체 이력 백테스트
```

주요 옵션:

| 옵션 | 설명 |
|---|---|
| `--format console\|markdown\|json` | 출력 형식 |
| `--out <경로>` | 파일로 저장 |
| `--as-of YYYY-MM-DD` | 과거 시점으로 평가 |
| `--adaptive-weight 0.0` | 퍼센타일 혼합 끄기 (고정 앵커만) |
| `--config <경로>` | 다른 전략 설정 사용 |

```

  indicators.py             지표 계산
  score.py                  계열 집계 → BCS / LRS / 합의 게이트
  strategy.py               밴드 → 사다리 → 히스테리시스 → 바닥선
  engine.py                 조립
  report.py                 콘솔 / 마크다운 / JSON
  cli.py
  datasources/              CoinMetrics · CSV · 수동입력

tools/screen_indicator.py   신규 지표 선별 검정

```

**의존성은 PyYAML 하나뿐이다.** 나머지는 표준 라이브러리로 구현했다.

```bash
python3 -m pytest tests/ -q      # 229 passed
```

네트워크 없이 전부 통과한다. 합성 시계열로 사이클 전 구간을 훑는 회귀 테스트가
포함돼 있다.

여기에 더해 **16년 실제 데이터(2010-07 ~ 2026-07, 5,854일)로 전략 전체를 하루씩
돌린 백테스트**가 있다. 이 검증으로 설계 결함 세 개를 찾아 고쳤다 —
상단 앵커의 노후화, 사다리 무한 재발동, 코어 지분 미보호.
자세한 내용은 [07 실측 검증](docs/07-실측-검증.md), 결과 보고서는
[reports/backtest-2026-07.md](reports/backtest-2026-07.md).

```bash
python3 tools/backtest.py --csv data/market.csv --out reports/backtest.md
python3 tools/screen_indicator.py --csv data/market.csv --out reports/screen.md
python3 tools/bottom_study.py --csv data/market.csv --out reports/bottoms.md
```

지표를 새로 넣으려면 먼저 `screen_indicator.py` 를 통과해야 한다. 선행 수익률과의
순위상관, 사분위 분리도, 기존 지표와의 중복도, 절대 수준의 안정성 네 가지를 본다.
이 관문으로 후보 6개 중 5개를 걸러냈다 —
자세한 내용은 [08 지표 선별](docs/08-지표-선별.md).

## 전략을 고치는 법

임계값은 코드가 아니라 `config/strategy.yaml`에 있다. 가중치, 앵커, 사다리 계단,
히스테리시스 파라미터를 전부 거기서 고친다.

설정을 읽을 때마다 아홉 가지를 검사한다 — 가중치 합 100, 밴드가 −100~100을 빈틈
없이 덮는지, 매도 사다리 누적이 코어 지분을 침범하지 않는지 등. 하나라도 어긋나면
프로그램이 시작하지 않는다. 가중치를 손으로 고치다 합이 97이 되는 실수는 언젠가
반드시 일어나고, 그때 조용히 잘못된 점수가 나오는 것보다 멈추는 편이 낫다.

## 알아둘 것

- **수동 입력이 절반이다.** RHODL, Reserve Risk, LTH 실현가격, CVDD, 거시 4종은
  무료 API가 없어서 BM Pro 차트를 보고 직접 넣는다. 월 1회면 충분한 느린 지표들이다.
  45일 지나면 경고, 120일 지나면 자동 결측 처리된다.
- **BCS는 ±10 정도의 오차를 안고 있다.** 입력 절반이 눈으로 읽은 값이다.
  −71.5와 −65는 사실상 같은 상황이다. 소수점을 근거로 행동을 바꾸지 마라.
- **앵커는 2025 사이클 실측에 맞춰져 있다.** 16년치로 검증하면서 상단 앵커를
  전면 재조정했다([07 실측 검증](docs/07-실측-검증.md)). 다음 사이클의 고점이
  더 낮으면 또 못 잡는다. 감쇠가 계속된다는 데 베팅하지 않고 관측된 마지막
  사이클에 맞췄을 뿐이다.
- **가중치와 사다리 트리거 자체는 여전히 백테스트로 최적화하지 않았다.** 표본
  사이클이 네 번뿐인 상황에서 최적화하면 과적합이 된다. 논리로 정하고
  [반증 조건](docs/06-한계와-반증조건.md#3-반증-조건)을 붙이는 쪽을 택했다.
- **보유자 행동 계열(가중치 25%)은 아직 실측으로 검증되지 않았다.** 수동 입력이라
  과거 이력이 없다. 무료로 대체할 수 있는지 찾아봤지만 후보 5개가 전부 탈락했다
  (거래소 지표는 신호 없음, 실현시총 증가율은 기존과 중복). 자동화하려면 유료
  데이터가 필요하다 — [08 지표 선별](docs/08-지표-선별.md#보유자-행동-계열은-여전히-미검증이다).
- **거래소 API 연동이 없다.** 의도적이다. 실행 버튼은 사람이 누른다.
